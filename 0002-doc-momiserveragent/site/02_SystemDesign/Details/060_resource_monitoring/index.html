    端末状態記録・送信詳細設計¶

    目的¶

    エージェントが導入されている端末の状態を取得・記録し、もみサーバで状態を確認できるようにします。

    Phase1取得項目¶

    項目 内容 Phase
    CPU CPU使用率を取得します。 Phase1
    GPU 存在するGPUの使用率を取得します。取得可否はOS・機器ごとに確認します。 Phase1
    Memory メモリ使用量と使用率を取得します。 Phase1
    Disk HDD/SSDの総容量、使用量、空き容量、使用率を取得します。 Phase1
    Temperature 取得可能なOS・端末ではCPU温度を取得します。 Phase1
    Network 送受信量や通信状態を取得します。 Phase2

    送信タイミング¶

    タイミング 内容
    定期送信 通常時は1分間隔で端末状態を送信します。
    稼働状態送信時 軽量な端末状態概要を稼働状態送信に含めます。
    バッチ実行前 実行前の端末状態を記録します。
    バッチ実行後 実行後の端末状態を記録します。

    取得・送信と負荷判定の合意¶

    2026年9月13日の合意として、以下の方針を採用します。

    項目 設定・扱い
    取得間隔 10秒ごと。送信抑制中も観測を継続します。
    通常の最短送信間隔 30秒。高負荷移行通知はこの制限を受けません。
    高負荷対象 CPU、存在するGPU、メモリの使用率です。
    高負荷判定 対象ごとに80%超を3回連続で検知します。いずれかが成立すれば高負荷に移行します。
    高負荷移行時 次の定期送信を待たずに通知し、詳細な端末情報の定期送信を抑制します。
    高負荷継続中 詳細な端末情報の定期送信を停止し、同じ高負荷の通知を繰り返しません。
    回復判定 全対象が80%以下の状態を3回連続で確認します。
    回復時 回復を通知し、詳細な端末情報の定期送信を再開します。

    80%ちょうどは高負荷条件に含めません。各連続判定は条件を満たさなくなった時点でリセットします。 取得不能な値を0%として扱ったり、回復を確認したことにしたりしません。 測定失敗時の連続回数の処理と監視対象の追加・削除手順は別途詳細化します。

    停止対象は詳細な端末情報の定期送信です。 軽量ハートビート、高負荷移行・回復通知、バッチの開始・結果通知、キャンセル受付は継続します。 送信失敗後の再送は下記の専用条件に従い、通常の最短送信間隔とは別に制御します。 回復通知と定期送信が近接する場合は通常の最短送信間隔を守り、必要に応じて同じ送信にまとめます。

    ディスク容量警告¶

    HDD・SSD等はI/O稼働率ではなく、ディスク容量の使用率をドライブ／マウント単位で判定します。 容量警告はCPU・GPU・メモリの高負荷と別管理とします。

    • 対象ごとに容量使用率が80%超の状態を3回連続で検知したら警告します。
    • 警告継続中は追加警告を抑制しますが、通常の端末情報送信は継続します。
    • 対象の容量使用率が80%以下の状態を3回連続で確認したら回復を通知します。
    • CPU・GPU・メモリの高負荷も発生している場合は、詳細な端末情報の送信抑制を優先します。
    • 抑制中の容量警告・回復の変化は最新状態として保持し、次の軽量ハートビートに含めます。

    容量警告を理由に送信を停止しても容量使用率は下がらないため、送信抑制の条件には含めません。

    通信失敗と最新値の保持¶

    項目 設定・扱い
    保持対象 最新の観測値と警告状態のみ。通信断中の観測履歴は蓄積しません。
    再送間隔 送信失敗から10秒ごと。
    再送回数 初回を除き3回、初回を含め最大4回。
    再送内容 最新値へ更新し、実際の取得日時を含めます。更新だけで再送回数をリセットしません。
    上限到達後 当該再送を終了し、次回の送信機会に最新値を含めます。古い値をまとめて送信しません。

    高負荷中に詳細な端末情報の送信を再送タイマーから再開しないよう、送信抑制状態も確認します。 軽量ハートビートによる生存確認は継続します。 警告についても最新状態を送る方式であり、通信断中の全状態遷移の履歴配送は保証しません。 バッチ結果の再送回数・保持期間とは別の方針です。 ハートビートと接続判定は接続管理詳細設計を参照します。

    記録項目¶

    項目 内容
    agent_id 端末を識別するAgent IDです。
    collected_at 端末状態を取得した日時です。
    cpu_usage_percent CPU使用率です。
    GPU情報 GPUごとの識別情報、使用率、取得可否を保持します。具体的な項目名は別途確定します。
    cpu_temperature CPU温度です。取得できない場合は未設定とします。
    memory_total メモリ総容量です。
    memory_used メモリ使用量です。
    memory_usage_percent メモリ使用率です。
    disk_total HDD/SSD総容量です。
    disk_used HDD/SSD使用量です。
    disk_free HDD/SSD空き容量です。
    disk_usage_percent HDD/SSD使用率です。
    send_status もみサーバへの送信状態です。

    ディスク項目はドライブ／マウントごとの識別情報とともに繰り返し保持します。 高負荷・送信抑制・容量警告の状態と送信理由も扱い、API上の項目名は別途確定します。

    利用用途¶

    用途 内容
    ダッシュボード表示 CPU温度、CPU使用率、Memory、Diskなどを管理画面へ表示します。
    バッチ実行判断 端末状態を確認し、過負荷時の実行抑制に利用します。
    異常検知 高負荷、容量不足、高温状態を検知します。
    運用分析 端末ごとの負荷傾向を確認します。
