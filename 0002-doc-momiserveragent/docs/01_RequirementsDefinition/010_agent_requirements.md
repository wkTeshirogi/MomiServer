# エージェント要件

## 基本方針

もみサーバエージェントは、AIエージェントではなくバッチ実行および端末状態送信用の常駐エージェントとして設計します。

Phase1では、バックエンドから通知されたバッチ実行要求を処理し、実行結果をバックエンドへ送信します。

あわせて、導入端末のCPU温度、CPU使用率、メモリ使用量、HDD/SSD容量などの端末状態を記録し、もみサーバへ送信します。

エージェントは常駐アプリとして動作し、端末起動後から停止指示または端末停止まで継続してバッチ実行要求の待受、端末状態の記録、もみサーバへの送信を行います。

Java、Python、Shell、Docker、Playwright、MCP、AIなどの汎用ジョブ実行機能は将来拡張とし、Phase1ではバッチ実行要求の処理に必要な範囲に限定します。

## 対応OS方針

Windows、Linux、macOSは必須対応とします。

AndroidまたはiOSは、どちらか一方に対応できればよいものとします。モバイル端末はOS制約が大きいため、PC/サーバ向けエージェントと同じジョブ実行機能を必須とはしません。

| 区分 | OS | 対応方針 | 主な役割 |
| --- | --- | --- | --- |
| 必須 | Windows | Phase1で対応します。 | バッチ実行、実行結果送信、端末状態記録、端末状態送信 |
| 必須 | Linux | Phase1で対応します。 | バッチ実行、実行結果送信、端末状態記録、端末状態送信 |
| 必須 | macOS | Phase1で対応します。 | バッチ実行、実行結果送信、端末状態記録、端末状態送信 |
| 任意 | Android | AndroidまたはiOSのいずれかで対応します。 | 端末情報送信、ハートビート、通知、軽量タスク |
| 任意 | iOS | AndroidまたはiOSのいずれかで対応します。 | 端末情報送信、ハートビート、通知、短時間タスク |

## 役割

| ID | 役割 | 内容 |
| --- | --- | --- |
| ROLE-001 | バッチ実行要求受信 | もみサーバからバッチ実行要求を受信します。 |
| ROLE-002 | バッチ実行 | 受信したバッチ実行要求に基づき、導入端末上でバッチ処理を実行します。 |
| ROLE-003 | 実行結果収集 | 実行時の標準出力、標準エラー、終了コード、実行時間を収集します。 |
| ROLE-004 | 実行結果送信 | バッチの開始、終了、エラー、タイムアウトをもみサーバへ通知します。 |
| ROLE-005 | 端末状態記録 | CPU温度、CPU使用率、メモリ使用量、HDD/SSD容量などの端末状態を記録します。 |
| ROLE-006 | 端末状態送信 | 記録した端末状態を定期的にもみサーバへ送信します。 |
| ROLE-007 | 常駐稼働 | 端末上で常駐し、バッチ実行要求の待受と端末状態送信を継続します。 |

## 基本情報

| 項目 | 内容 |
| --- | --- |
| エージェントID | UUIDで一意に識別します。 |
| エージェント名 | 管理画面やログで識別しやすい名称を保持します。 |
| バージョン | エージェント本体のバージョンを保持します。 |
| OS | 稼働端末のOS種別とバージョンを保持します。 |
| ホスト名 | 稼働端末のホスト名を保持します。 |
| IP | 稼働端末のIPアドレスを保持します。 |
| MAC | 稼働端末のMACアドレスを保持します。 |

## 接続管理要件

| 項目 | 内容 |
| --- | --- |
| ハートビート | エージェントが稼働中であることを定期的に送信します。 |
| 最終接続 | 最後にもみサーバへ接続できた日時を保持します。 |
| 接続状態 | Online、Offline、Errorなどの状態を管理します。 |
| 認証トークン | もみサーバとエージェント間の認証に使用します。 |
| TLS対応 | 通信経路を保護できるようにします。 |

## Phase1機能要件

| ID | 要件 | 内容 |
| --- | --- | --- |
| FR-001 | エージェント登録 | エージェントをもみサーバへ登録できること。 |
| FR-002 | 認証 | 登録済みエージェントとして認証できること。 |
| FR-003 | 稼働状態送信 | エージェントの稼働状態を定期的にもみサーバへ送信できること。 |
| FR-004 | バッチ実行要求受信 | バックエンドから通知されたバッチ実行要求を受信できること。 |
| FR-005 | バッチ実行 | Windows、Linux、macOSでバッチ実行要求に基づく処理を実行できること。 |
| FR-006 | 実行ログ収集 | stdout、stderr、ExitCode、実行時間を収集できること。 |
| FR-007 | 実行結果送信 | バッチの完了状態と結果をもみサーバへ送信できること。 |
| FR-008 | 端末状態記録 | CPU温度、CPU使用率、メモリ使用量、HDD/SSD容量などを記録できること。 |
| FR-009 | 端末状態送信 | 記録した端末状態をもみサーバへ送信できること。 |
| FR-010 | ローカル一時保持 | 通信失敗時に実行結果や端末状態を一時保持し、再送できること。 |
| FR-011 | 常駐稼働 | OS起動後に常駐アプリとして起動し、停止指示まで継続稼働できること。 |
| FR-012 | 常駐中の待受 | 常駐中にバックエンドからのバッチ実行要求を継続して待ち受けできること。 |
| FR-013 | 常駐中の定期送信 | 常駐中に端末状態を定期的にもみサーバへ送信できること。 |
| FR-014 | 実行環境設定 | 実行環境にデフォルトを設け、端末側の設定ファイル等で変更できること。 |
| FR-015 | 共通実行制御 | サーバ側の共通設定に従って同時実行数、タイムアウト、キャンセルを制御できること。 |
| FR-016 | 重複実行防止 | 実行IDと処理状況を永続化し、再配信・エージェント再起動後も同一実行IDを二重実行しないこと。 |
| FR-017 | 再実行判断の集約 | バッチの再実行はサーバ側で判断し、新しい実行IDで要求すること。 |
| FR-018 | 結果送信管理 | 実行結果と送信状態を分離し、規定回数の再送と期限付きの未送信結果保持を行うこと。 |
| FR-019 | 結果不明の管理 | サーバ側の結果待ち期限で結果不明を判定し、遅れて届いた確定結果を同じ実行IDに反映できること。 |

設定値と適用範囲は[実行制御詳細設計](../02_SystemDesign/Details/040_execution_control.md)、
再送・結果不明の扱いは[ログ・結果通知詳細設計](../02_SystemDesign/Details/050_log_result_notification.md)を参照します。

## Phase1バッチ実行機能

| 機能 | 内容 |
| --- | --- |
| 実行要求受信 | バックエンドからバッチ実行要求を受信します。 |
| 実行前準備 | 実行コマンド、作業ディレクトリ、タイムアウト秒数などを確認します。 |
| バッチ実行 | 導入端末上で指定されたバッチ処理を実行します。 |
| 結果収集 | 終了状態、終了コード、実行時間、ログ参照情報を収集します。 |
| 結果送信 | 収集した実行結果をもみサーバへ送信します。 |

## Phase1端末状態取得機能

| 項目 | 内容 |
| --- | --- |
| CPU温度 | 取得可能なOS・端末ではCPU温度を取得します。 |
| CPU使用率 | CPU使用率を取得します。 |
| メモリ使用量 | メモリ総容量、使用量、使用率を取得します。 |
| HDD/SSD容量 | ディスク総容量、使用量、空き容量、使用率を取得します。 |
| 取得日時 | 端末状態を取得した日時を記録します。 |
| 送信状態 | もみサーバへの送信成否を記録します。 |

## モバイル対応要件

| ID | 要件 | 内容 |
| --- | --- | --- |
| MFR-001 | 対応優先度 | AndroidまたはiOSのどちらか一方に対応できればよいこと。 |
| MFR-002 | 機能差分 | モバイル端末ではPC/サーバ向けと同等のジョブ実行を必須としないこと。 |
| MFR-003 | 端末情報送信 | 取得可能な範囲で端末情報、アプリ状態、接続状態を送信できること。 |
| MFR-004 | ハートビート | OS制約の範囲で稼働状態または最終同期状態を送信できること。 |
| MFR-005 | 通知 | もみサーバからの通知や状態変化を端末へ通知できること。 |
| MFR-006 | 軽量タスク | OSが許可する範囲で短時間の同期や軽量処理を実行できること。 |

## Phase2拡張候補

| 機能 | 内容 |
| --- | --- |
| Docker実行 | コンテナを利用したジョブ実行に対応します。 |
| PowerShell実行 | Windows環境向けのPowerShellジョブに対応します。 |
| Node.js実行 | Node.jsスクリプトの実行に対応します。 |
| Playwright実行 | ブラウザ自動操作ジョブに対応します。 |
| MCP実行 | MCP連携ジョブに対応します。 |
| AI実行 | AIを利用するジョブをPluginとして実行します。 |
| モバイル対応 | AndroidまたはiOS向けの制限付きエージェントに対応します。 |
| 管理エージェント | サービス状態取得、ログ収集、インベントリ送信を強化します。 |
| 自己更新 | もみサーバから通知された新バージョンへ更新します。 |

## 非機能要件

| ID | 要件 | 内容 |
| --- | --- | --- |
| NFR-001 | 拡張性 | 実行方式や管理機能をPluginとして追加できること。 |
| NFR-002 | 安定性 | 常駐型ソフトウェアとして継続稼働できること。 |
| NFR-003 | 制御性 | バッチ実行の同時実行数とタイムアウトを制御できること。 |
| NFR-004 | 監視性 | バッチ実行状態、実行ログ、端末状態を追跡できること。 |
| NFR-005 | 安全性 | バックエンドから許可されたバッチ実行要求のみを処理できること。 |
| NFR-006 | モバイル適合性 | モバイルOSのバックグラウンド実行制約に合わせて機能を制限できること。 |
| NFR-007 | 常駐性 | バックグラウンドで稼働し、画面操作を前提とせずに待受と送信を継続できること。 |
