# インフラ設計

## ビルド・配布方針

Windowsを通常エージェントのビルド・配布物作成の中心環境とします。
実装言語の採用理由は[エージェント基本設計](../02_SystemDesign/010_agent_basic_design.md)を参照します。

初期の配布形式は、OS・CPUごとの実行ファイル、設定例、導入・解除スクリプト、Markdownの導入手順を含むアーカイブとします。
OS固有のインストーラー化は、必要に応じて追加します。

| 対象OS | GoのGOOS指定 | 初期配布形式 | 常駐方式 |
| --- | --- | --- | --- |
| Windows | windows | ZIP | Windowsサービス |
| Linux | linux | tar.gz | systemdを前提とします。非systemd環境の対応は別途検討します。 |
| macOS | darwin | tar.gz等のアーカイブ | launchd |

対応CPUは未確定です。amd64とarm64を候補として、導入端末に合わせて対象を確定します。
対応するOSバージョン、Linuxディストリビューション、macOSでの配布形式の詳細も別途確定します。

## Windows上での作成手順の設計

1. Goのバージョンと依存ライブラリのバージョンを固定します。
2. PowerShellによるビルド処理で、対象ごとにGOOSとGOARCHを指定します。
3. CGO_ENABLED=0を基本として、各対象の実行ファイルを生成します。
4. 対象OS向けの設定例、サービス登録・解除スクリプト、導入手順を同梱します。
5. OS・CPU・バージョンを識別できる名前でアーカイブを作成します。

Linux・macOS向けアーカイブでは実行権限とスクリプトの改行コードを適切に扱います。
Windows上で作成できたことと、対象OSで正常に動作することは別に検証します。
ビルドスクリプト、インストーラー、配布物は今後実装します。

## 依存ライブラリの選定条件

端末情報収集、MQTT通信、ローカル永続化等のライブラリは、3OSへの対応とCGO_ENABLED=0でのビルド可否を確認します。
C連携が必要な依存を採用すると対象環境用のCコンパイラー等が必要になるため、純Goで実現できるものを優先します。
CGO_ENABLED=0だけで、すべてのOS機能や外部ツールへの依存がなくなるとは扱いません。

バッチ処理状況・結果再送情報の保存方式はJSONファイルに決定しています。
保存単位・更新・復旧方針は[ログ・結果通知詳細設計](../02_SystemDesign/Details/050_log_result_notification.md)を参照します。
具体的なライブラリとGoの採用バージョンは未確定です。
Go本体・依存ライブラリの修正は、再ビルドと再配布によって取り込む運用とします。

## OS固有の配布工程と動作検証

アーカイブ配布物はWindows上で作成する方針ですが、署名、公証、OS固有インストーラーまで
Windowsだけで完結することは前提としません。
macOSの一般配布向け署名・公証が必要になった場合は、macOS環境を使用する工程を設けます。
署名証明書、署名・公証の実施範囲、CI環境、更新・切り戻し手順は別途確定します。

配布前にWindows・Linux・macOSの各対象環境で、以下を確認します。

- インストール、常駐起動、停止、アンインストール。
- CPU・メモリ・ディスク・ネットワーク等の情報取得と、取得不可項目の扱い。
- バッチ実行、タイムアウト、キャンセル時の子プロセスを含む停止。
- 設定ファイルと永続化データの配置・権限、通信断・再起動後の結果再送と重複防止。
