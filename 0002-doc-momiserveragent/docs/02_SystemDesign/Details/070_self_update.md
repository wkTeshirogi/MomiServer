# 自己更新詳細設計

## 目的

もみサーバからエージェントの新バージョンを配信し、端末上のエージェントを更新できるようにします。

## 更新フロー

```text
もみサーバ
  |
  | 新バージョン通知
  v
エージェント
  |
  | 更新パッケージ取得
  v
更新準備
  |
  | 実行中ジョブ確認
  v
更新
  |
  | 再起動
  v
新バージョンで起動
```

## 更新条件

| 条件 | 内容 |
| --- | --- |
| バージョン差分 | サーバ側の配信バージョンが現在バージョンより新しいこと。 |
| 認証済み | 更新指示が認証済みのもみサーバから送信されていること。 |
| 実行状態 | 更新可能なタイミングであること。 |
| 整合性確認 | 更新パッケージの破損や改ざんがないこと。 |

## 更新時の扱い

| 事象 | 対応 |
| --- | --- |
| 実行中ジョブあり | 更新を待機するか、管理者設定に従って更新します。 |
| 更新成功 | 新バージョンで再起動し、ハートビートでバージョンを通知します。 |
| 更新失敗 | 旧バージョンへ戻すか、Error状態として通知します。 |
| 再起動失敗 | もみサーバへ異常状態を通知できる仕組みを検討します。 |
