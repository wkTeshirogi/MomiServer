# エージェント登録詳細設計

## 目的

エージェントをもみサーバへ登録し、管理対象として識別できるようにします。

## 登録情報

| 項目 | 内容 |
| --- | --- |
| エージェントID | バックエンドが事前登録時にUUIDを採番し、端末登録時に取得します。 |
| エージェント名 | 管理者が識別しやすい名称を設定します。 |
| バージョン | エージェント本体のバージョンを登録します。 |
| OS | OS種別とバージョンを登録します。 |
| ホスト名 | 端末のホスト名を登録します。 |
| IP | 端末のIPアドレスを登録します。 |
| MAC | 端末のMACアドレスを登録します。 |
| Capability | 実行可能な機能を登録します。 |
| Label | ジョブ割当に使用する条件を登録します。 |
| タグ | 検索や分類に使用するタグを登録します。 |

## 処理フロー

この節は常駐化・MQTT連携後を含む目標フローです。現在の実装範囲は下記「2026年9月23日の実装仕様」を参照してください。

2026年9月13日の合意として、管理画面で基本情報を事前登録し、登録コードで実端末を紐付けます。

1. 管理画面でエージェント名・対象マシン等を登録し、登録コードを発行します。
2. 端末で登録CLIを実行し、設定ファイルまたはオプションからバックエンドURLを取得します。
3. 初回送信前に登録要求IDを生成・保存し、OS・ホスト名・バージョン等とともにHTTPSで送信します。
4. バックエンドが返したエージェントID・専用認証情報・MQTTクライアントID・接続設定を保存します。
5. 保存完了後、共通設定取得、MQTT接続、ハートビートを開始します。

コードの生成と照合はバックエンド、発行操作と表示は管理画面が担当します。
登録状態と接続状態は別管理とし、登録成功だけでOnlineとは判断しません。

## 登録結果の保存と再試行

### 登録CLI

2026年9月13日の合意として、Windows・Linux・macOS共通でCUIから初回登録できるようにします。
LinuxのSSH接続・コンソールのみの環境でも、端末側にGUIやブラウザーを必要としません。
管理画面の操作は手元のPCなど別端末から行えます。

| 操作 | コマンド形式 | 動作 |
| --- | --- | --- |
| 基本の初回登録 | `momiserver-agent register <登録コード>` | 引数でコードを受け取り、設定ファイルのバックエンドURLへ登録します。 |
| 接続先の明示 | `momiserver-agent register <登録コード> --server https://example.com` | 設定ファイルより明示したURLを優先します。 |
| 対話入力 | `momiserver-agent register` | コードを省略した場合、入力文字を表示しない対話入力で受け取ります。 |

表中の登録コードは管理画面で発行するコードであり、登録後の専用認証情報とは区別します。
接続先URLを解決できない場合は登録を開始せず、設定またはオプションの指定を案内します。
対話入力できない環境でコードが省略された場合は、待機し続けず入力不足として終了します。

引数のコードはシェル履歴やプロセス一覧に残る可能性があります。
コード引数を使う方式を提供したうえで、露出を避けたい場合は非表示の対話入力を選択できるようにします。
コードの有効期限・利用回数はバックエンドとの登録契約に従い、CLIのログやエラーにコードを再表示しません。

### 結果表示と常駐サービスへの引継ぎ

登録成功時は、認証情報の保存が完了したこととエージェントIDを表示します。
認証情報そのものは表示しません。バックエンドでの登録受理、ローカル保存完了、
API通信・MQTT接続の成否を区別して案内します。
MQTT接続だけが失敗した場合は、登録失敗として新規登録を繰り返さず、保存済み情報で接続を再試行します。

登録CLIと常駐サービスは同じ設定・認証情報の保存先を利用します。
SSHログインユーザーとサービス実行ユーザーが異なる場合も引き継げるよう、
OS別の共通保存先とアクセス権を定義します。
明示したバックエンドURLは、保存した認証情報がどの接続先に対応するか判別できるよう保持します。
サービス登録・起動コマンドの詳細と登録CLIからの自動起動の有無は、運用設計で別途確定します。

### 認証情報の保存と再試行

認証情報は実行ユーザーにアクセスを制限した領域へ保存し、通常ログに出力しません。
保存形式・OS別保存先は下記の実装仕様を参照します。バッチ結果のJSONと同じファイルには格納しません。
通常の再起動・MQTT再接続では保存済みのIDと認証情報を再利用し、コードを毎回要求しません。

応答消失や保存失敗では同じ登録要求IDで再試行し、新しいIDで登録を重複作成しません。
登録前に保存したEd25519鍵で、新しいnonceを含むJWSへ署名して確認します。
登録要求IDだけで認証情報を再取得できる設計にはしません。
認証情報を安全に取得・保存するまで、端末側の登録手順が完了したとは扱いません。

期限切れ・無効なコードは管理画面での再発行を案内します。
登録済み設定を別端末へコピーせず、端末交換は管理画面から明示的に再登録します。

認証方式・保有証明・API項目・エラーはバックエンド設計の `0005_agent_authentication.md` と

## 状態

| 状態 | 内容 |
| --- | --- |
| Unregistered | もみサーバへ登録されていない状態です。 |
| Registered | 登録済みで、認証情報を保持している状態です。 |
| Online | ハートビートが成功している状態です。 |
| Offline | 一定時間ハートビートが確認できない状態です。 |
| Error | 登録または認証に失敗している状態です。 |

## 2026年9月23日の実装仕様

Go製CLIのregister / refresh / statusを実装しました。registerは `POST /api/v1/agent/register` を使用します。
開発用`--allow-insecure-localhost`を追加済みです。明示した実行に限りループバックへのHTTPを許可します。使い方・接続先制限・専用鍵の準備・障害対応は[登録・認証テスト操作手順](../../07_OperationsDesign/010_registration_test_guide.md)を参照してください。
challengeで取得したnonceにEd25519 JWSで署名し、登録・更新の要求IDとコード／更新トークンのSHA-256を結び付けます。
管理ユーザーのJWTや外部APIキーは利用しません。

| OS | 共通保存先 |
| --- | --- |
| Windows | `%ProgramData%\MomiServer\agent` |
| Linux | `/var/lib/momiserver-agent` |
| macOS | `/Library/Application Support/MomiServer/agent` |

--state-dirで変更できます。CLIと将来の常駐サービスは同じパス・実行アカウントを使用します。
Windowsは実行アカウントとSYSTEM、UNIXは所有者だけにアクセスを制限します。
接続先は--server、保存先内のconfig.jsonのserver、保存済み接続先の順です。
秘密鍵・要求ID・資格情報はcredentials.jsonに保存し、平文登録コードは保存しません。原子的置換とOSファイルロックで保存します。

statusは必要に応じて更新し、me APIで認証を確認します。refreshは明示更新です。
--reregisterは管理者が再登録を開始した後、新コードへの切り替えに使用します。同じ登録途中の再試行では鍵・要求IDを維持します。
終了コードは成功0、失敗1です。資格情報自体を表示しません。

runによるMQTT接続・常駐更新・実行ループ・軽量ハートビートを追加しました。
定義添付の取得・検証・実行と作業ディレクトリの期限後回収も実装済みです。
OSサービス自動登録、詳細端末監視、成果物アップロードは未実装です。
導入手順の正本はバックエンド設計の `docs/07_OperationsDesign/0004_agent_batch_runtime.md` です。

## MQTTブローカーの採用決定

2026年9月23日、MQTTブローカーは当面Eclipse Mosquittoを採用することに決定しました。
Agent専用の接続認証・権限・失効連携を追加しました。既定は無効です。登録後、runが設定取得APIから現在の同期状態・専用接続情報を取得します。
Dynamic Securityを利用する案とバックエンド側の責務は、バックエンド設計リポジトリの `docs/02_SystemDesign/認証/0005_agent_authentication.md` の「MQTTの境界」を正とします。
Agent側は専用のMQTT資格情報をHTTPトークンと区別して保護し、指定されたClient ID・登録世代・トピックに従って接続する方針です。
