# モバイル対応詳細設計

## 目的

AndroidまたはiOSのどちらか一方に対応し、モバイル端末をもみサーバの管理対象として扱えるようにします。

モバイル端末はPC/サーバ向けの通常エージェントとは異なり、OSのバックグラウンド実行制約を前提とした制限付きエージェントとして設計します。

## 対応方針

| OS | 対応方針 | 備考 |
| --- | --- | --- |
| Android | 対応候補とします。 | 通知付きのバックグラウンド処理やスケジュール実行を検討します。 |
| iOS | 対応候補とします。 | 短時間のバックグラウンド処理、Push通知、アプリ起動時同期を中心に検討します。 |

AndroidまたはiOSのどちらを優先するかは、実装容易性、取得したい端末情報、運用目的をもとに決定します。

## 通常エージェントとの差分

| 項目 | 通常エージェント | モバイルエージェント |
| --- | --- | --- |
| 対象OS | Windows、Linux、macOS | AndroidまたはiOS |
| 常駐性 | 常駐プロセスとして継続稼働します。 | OS制約に従い、常時稼働を前提にしません。 |
| ジョブ実行 | Java、Python、Shellなどを実行します。 | 任意コマンド実行は必須としません。 |
| ログ収集 | stdout、stderr、ExitCode、実行時間を収集します。 | アプリログ、同期結果、通知結果を中心に扱います。 |
| 監視 | CPU、Memory、Diskなどを取得します。 | 取得可能な端末情報に限定します。 |
| 自己更新 | エージェント自身で更新します。 | 各アプリストアまたは配布方式に従います。 |

## 機能範囲

| ID | 機能 | 内容 |
| --- | --- | --- |
| MOB-001 | 端末登録 | モバイル端末をエージェントとして登録します。 |
| MOB-002 | 認証 | モバイル端末からもみサーバへ認証します。 |
| MOB-003 | 状態同期 | アプリ状態、最終同期日時、接続状態を送信します。 |
| MOB-004 | 端末情報送信 | OS、端末名、アプリバージョンなど取得可能な情報を送信します。 |
| MOB-005 | 通知受信 | もみサーバからの通知を受信します。 |
| MOB-006 | 軽量タスク | OSが許可する範囲で短時間の同期処理を実行します。 |

## 非対応範囲

| 項目 | 理由 |
| --- | --- |
| 任意Shell実行 | モバイルOSのセキュリティ制約により通常エージェントと同じ実行方式にできないため。 |
| 常時ジョブ待受 | バックグラウンド実行がOSにより制限されるため。 |
| 自己更新 | モバイルアプリの更新は配布方式やストア審査に従う必要があるため。 |

## Go利用方針

Goで共通ロジックを実装する場合、通信、認証、データモデル、同期処理などの共通部分を共有対象とします。

モバイル固有のUI、通知、バックグラウンド実行、権限管理は、各OSのネイティブ層で実装します。

## 判定基準

| 判定項目 | Android | iOS |
| --- | --- | --- |
| バックグラウンド処理 | 比較的対応しやすいです。 | 制約が強く、短時間処理中心です。 |
| 通知連携 | 対応候補です。 | 対応候補です。 |
| 端末情報取得 | 取得できる項目を確認します。 | 取得できる項目を確認します。 |
| 配布方式 | APK配布やストア配布を検討します。 | ストア配布や検証用配布を検討します。 |
| 優先度 | 第一候補とします。 | 第二候補とします。 |

## 推奨方針

Phase2では、Androidを第一候補としてモバイルエージェント対応を検討します。

iOSは、通知、状態同期、アプリ起動時の情報送信を中心とした管理クライアントとして検討します。
