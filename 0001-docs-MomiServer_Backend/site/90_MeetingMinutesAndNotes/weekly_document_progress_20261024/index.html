    サマリ¶

    10月16日の残対応「一覧ページングの総件数・取得上限・更新中動作の横断照合」を実施した。 130_meeting_minutes.mdテンプレートを使用した。 調査結果の詳細と残対応は一覧ページング横断照合へ集約する。

    決定事項¶

    No 内容
    1 今回は照合と記録のみとし、アプリの修正・API契約変更は行わない
    2 表示件数と取得件数を区別し、全件取得方式を100件上限と誤記しない
    3 要修正、挙動統一候補、仕様確認を区別し、調査完了を不具合解消とは扱わない

    共通設計 車両・外部APIキーを適用一覧へ補足し、API取得上限と表示件数の区別を明記
    新規文書 テスト設計テンプレートから横断照合記録を作成
    Git 3リポジトリでstatus・fetch・mainとの差分を確認。文書用ブランチ作成。既存変更を保持

    ユーザー指定の2項目に限定して、既存の日時表示とAPIエラー抽出の重複を整理した。 APIキー、APIログ、Agent、添付ファイル、実行ログを共通表示へ移行し、既存utils経由の利用も維持した。 通知・バッチ共通設定、通知ルート、車両取込、個人設定、ユーザー管理等のエラー抽出を共通化した。

    区分 内容
    日時表示 zone付き時刻は日本時間へ変換。zoneなしのAPI日時はBEと同じ日本時間として解釈
    表示の互換 ミリ秒の有無と未設定ラベルを指定可能。APIキーの時刻は0埋めへ統一
    対象外を維持 車検日付、日付・日時入力、Cron・カレンダー計算、認証フロー、API契約は変更しない
    エラー抽出 Axiosと生成SDKの本文形式、旧形式の文字列・項目別エラーを吸収
    業務分岐 画面固有の代替文言、400・409分岐、フォーム項目名、通知位置・入力保持を維持
    非表示 生の通信Error・request・config・stack・rejectedValueを表示せず、HTML等は代替文言へ戻す
    CI Node.js 24の組み込み単体試験をfrontend_unit_testとしてvalidateへ追加。追加依存なし
    文書 040・090テンプレートを基に基本設計と試験設計を追加
    検証 結果
    単体試験 npm run test:unitで35件成功。UTC・東京・米国西海岸、日付境界、不正日時、エラー形式・機密非表示を確認
    画面回帰 npm run test:e2eで84件成功。模擬APIで権限、通知位置、入力保持、競合・認証の回帰を確認
    静的検証 npm run build・npm run lint成功。CI YAML解析とvalidate単体試験ジョブの定義確認が成功
    CLI 米国時間のブラウザで日本時間を表示。HTML非表示と通知の収まり、SDKの項目別エラー・入力保持を明示的に確認
