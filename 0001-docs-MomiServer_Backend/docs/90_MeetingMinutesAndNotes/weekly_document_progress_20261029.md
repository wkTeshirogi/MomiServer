## 検証中に確認した課題

- Windowsの既定一時領域を使ったJava NIOのループバック接続でGradle起動が失敗した。
  検証プロセスだけに専用のjdk.net.unixdomain.tmpdirを指定して解消し、OS・既存アプリの設定は変更しない。
- ref確定後の応答を黙って破棄する初期fixtureは、クライアントの待機が長引いた。
  最終試験は成功応答をHTTP 502へ置換する明示的な応答障害注入とし、実際の通信切断試験と区別した。
- Gitは子のHTTPSプロセスを起動する。中断時は試験所有のプロセスツリーだけを停止する実装へ修正した。
- 一時Linuxコンテナの既定NATは起動に失敗したため、Podman VMのhostネットワークを使用した。
  サーバーはループバックの動的ポートのみ。既存NAT・ファイアウォール設定は変更しない。

## 追加合意: Git履歴保持と容量管理

通常の履歴をrepo物理削除まで保持する一方、削除branch・履歴書換え前の到達不能履歴まで永久保存する要件は設けない。

## 追加合意: 共通設定・作業判定・保持世代

ユーザーが猶予・保持世代案を承認し、clone・fetchは作業対象に含めないと回答した。
Git制限値と作業判定期間はADMIN向け共通設定から変更可能とする。
初期90日の利用状況判定は成功push・repo設定変更だけを対象とし、取得アクセスや監視・バックアップで更新しない。
repo保守は当面、利用状況の状態管理のみ。無効化・削除・GC等を状態判定だけで自動実行しない。
論理削除猶予30日、到達不能履歴の復旧猶予・reflog保持90日、月次フル3世代・週次差分8世代を確定した。
差分が必要とするフルは上限超過でも保護し、更新直前の別取得は更新確認後も7日間保持する。
前段の記録で未確定としていた猶予日数と保持世代は、この追加合意を最新とする。
FR-0056と基本・運用設計、判断記録、タスク一覧を追従更新し、保守実行機能は将来タスクとして分離した。
共通設定の画面・API・DB、状態判定処理、自動清掃、バックアップ処理自体は実装していない。
残件は初期制限値、正式パス・CA・外部退避先、取得時の停止時間・未取得予定や失敗時の再実行条件とする。
全docsのMarkdown lint・MkDocs strict・差分検査に成功した。状態判定の実行試験ではなく文書整合性の確認とする。
