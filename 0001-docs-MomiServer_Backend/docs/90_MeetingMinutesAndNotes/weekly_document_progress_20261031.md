## 残課題・注意事項

- GitLab上の実CI・SonarQubeサーバー再解析はcommit・push後に確認が必要。今回はcommit・pushをしない。
- BEのスキップ22件、CI補助の環境依存スキップ、登録・在庫競合等の全要件対応表は残る。
- 旧Agentでは保守時の開始保留応答に対応できない。導入は新Agentを先とし、実機で順序・再起動・長時間停止を受入確認する。
- 単一BEの保守機能であり、バッチ以外の書込停止・自動systemd更新・バックアップ一連を実装したものではない。
- 容量警告の通知、ディスク故障・未永続化の結果、緊急ADMIN・停止中通知は別の残件として維持する。
- Git管理UI・CI/CD・専用通知・Git本体組込みは後続対象。完了済み基本設計は差し戻さない。
- 既存のステージ済み文書・JGit検証、未追跡の個人用バッチ・画像を保持した。
- Sol Advisorは利用者確認済みSol / High、solo経路。共通Clockの独立レビュー実施とは扱わない。
- 参照規約: 共通方針README、Javaコーディング規約、Goコーディング規約、定数定義方針、FE通知表示方針。

## 同日のSonarQube再解析への対応

取得済みの`20261031T021201Z_momiServer_1252c0ad/issues.json`と`quality_gate.json`を確認した。
未解消22件はBLOCKER 1件、CRITICAL 7件、MAJOR 6件、MINOR 8件。
品質ゲート失敗は新規指摘20件によるもので、新規コードのカバレッジ88.4%、重複率、Hotspotレビュー条件は通過していた。
ゲートや解析ルールを緩和せず、新規・既存を含む22件に対応した。

| 指摘・対象 | 修正方針 |
| --- | --- |
| OCRのExecutor解放 | try-with-resourcesで所有し、終了・例外時のプロセス停止とshutdownNowを先に行ってからExecutorを閉じる |
| Agentの登録・実行状態 | 既存の登録状態・バッチ実行状態Enumを参照し、英語の保存値を維持 |
| MQTT・添付の状態 | 用途別Enumを追加し、別の状態と同一の文字列だからという理由で共通化しない |
| 開始処理の複雑度 | 受付ゲート・トランザクションを維持し、ロック下の開始処理と期限検証を分離 |
| 添付登録の引数数 | 不変の保存メタデータへまとめ、登録要求ID・置換・保存・ロールバック契約を維持 |
| 冗長代入・コメント・テスト | 検証呼出しを維持して冗長代入だけ削除。dangling JavaDoc、例外検証ラムダ、未使用importとAssertJ記法を修正 |
