## 発生事項と対応

| 区分 | 内容 | 影響 |
| --- | --- | --- |
| Windowsサービス参照 | 既存実装がSCMとサービスへ全権限を要求し、非管理者Agentではアクセス拒否となった | `SC_MANAGER_CONNECT`と`SERVICE_QUERY_STATUS`だけを要求する実装へ変更し、EventLogの`online`とPID取得を確認 |
| Gradle実行環境 | Windows側のJavaプロセスがNIOループバック初期化で失敗した | 既存のPodman JDK 25イメージでCI相当コマンドと`bootJar`を実行。プロジェクトのテスト失敗ではない |
| 開発用初期データ | V2のコメントはパスワードを`password123`としているが、保存済みBCryptハッシュは`password`に対応する | 適用済みマイグレーションのチェックサムを変えないためV2は変更せず、別途修正対象として記録 |
| ハードウェア情報 | CPU・GPU温度は検証端末で取得できなかった | OS・ハードウェア依存の正常な欠損として画面の未取得表示を確認 |

## 残課題

| 優先度 | 作業 | 目的 |
| --- | --- | --- |
| 中 | 開発用管理者パスワードの説明を、適用済みV2を変更しない方法で訂正する | Flywayチェックサムを維持しながら運用時の誤認を防ぐ |
| 低 | Windowsサービス状態参照の権限マスクとハンドル解放を自動テストで固定する | 将来の変更で全権限要求へ戻る回帰をCIで検出する |

| 低 | macOS実機で状態収集を確認する | 現時点のサービス状態取得はWindowsとLinuxが対象 |
