## 主な設計判断

- 調査済み、仕様確定、実装済み、検証済みを区別し、文書上の状態を明示する。
- 一覧APIと画面は共通ページング契約へ寄せ、件数、取得失敗、データ増減時の整合を確認する。
- APIキーの原文は発行時だけ表示し、保存値はハッシュ化する。発行、失敗、無効化の通知表示先を分離する。
- 車検更新は現在の満了日を基準とし、閏日補正、履歴、楽観的競合、権限制御を含める。
- 日時取得は共通Clockへ統一し、業務日付、日本時間表示、JWTの絶対時刻を用途別に扱う。
- フロントエンドの日時表示とAPIエラー処理は共通化し、機密情報を画面へ露出しない。
- CI定義の静的確認と実パイプライン成功、モックE2Eと実バックエンド結合を明確に区別する。

## 実装・ドキュメント整合

月前半はGateway Phase 1、通知、タスク・Agent状態、APIアクセスログを中心に、要件からテストまでの不足を補った。
中盤は車検期限通知と外部APIキー・在庫連携を追加し、API・DB・画面・権限・監査の契約を整理した。
後半は一覧ページングの横断照合から、外部APIキー画面、SonarQube指摘、車検更新、個人設定、共通Clock、フロントエンド共通処理、定数配置まで横断的な共通化を進めた。
