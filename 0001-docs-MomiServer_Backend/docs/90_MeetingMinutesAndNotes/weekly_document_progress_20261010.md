# Agent実測状態連携・週次ドキュメント更新メモ 2026/10/10

## サマリ

マシン・サービスステータス画面がマスタとHeartbeatだけを表示していた状態から、
Agentが収集した端末リソース、OSサービス、プロセスの実測状態を表示する構成へ更新した。
既存のAgent専用認証とWebSocket配信境界を維持し、担当外サービスや旧登録世代の状態を採用しない。

## 決定事項

| No | 内容 | 理由 |
| --- | --- | --- |
| 1 | 状態スナップショットをHeartbeatから分離する | 軽量な生存確認と可変量の実測情報を別契約にするため |
| 2 | 監視対象サービスはバックエンドからAgentへ配布する | Agentのローカル設定とサービスマスタの不整合を防ぐため |
| 3 | WindowsはSCM、Linuxはsystemdを状態の正本とする | プロセス名推測ではなくOSサービス管理状態を利用するため |
| 4 | 状態コードは`online`、`offline`、`unknown`とする | 保存値を英語コードへ統一する方針に合わせるため |
| 5 | 現在世代かつ3分以内の実測値だけを画面へ採用する | 再登録前・停止Agentの古い値を表示しないため |

## 作業内容

| 区分 | 内容 |
| --- | --- |
| Agent | CPU、メモリ、ストレージ、温度、OS稼働時間、サービス状態、PID、プロセス使用率・稼働時間を1分間隔で収集 |
| バックエンド | Agent専用の監視対象取得API・状態登録API、認可・値域検証、最新状態テーブル、表示スナップショット統合を追加 |
| フロントエンド | 実測稼働時間を表示し、未対応のゲーム固有メトリクスを未取得として分離 |
| 設計 | API-0042、API-0045、画面設計2件、テーブル定義3件、DB索引を更新 |

## 残作業・注意事項

- V31マイグレーション適用後に、実Agentから状態が登録されWebSocketへ反映される結合確認を行う。
- macOSのlaunchd連携、ゲーム固有メトリクス、Disk IO・Network IOは後続対応とする。
- 温度はOS・ハードウェア・実行権限によって取得できないため、未取得を正常系として扱う。
- 既存作業ブランチと未コミット変更を維持し、commit・pushは行わない。
