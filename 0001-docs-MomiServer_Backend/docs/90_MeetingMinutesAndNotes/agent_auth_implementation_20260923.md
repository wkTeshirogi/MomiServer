# Agent登録・専用認証・端末認可 実装記録 2026/09/23

## サマリ

端末マスタからの登録コード発行、HTTP専用認証、端末と登録世代による既存Agent APIの認可、Go登録CLIを実装した。
作業ブランチは対象5リポジトリともagent-registration-auth。以前からの未コミット変更を保持し、コミット・pushは行わない。

## 決定事項

- コード発行は端末マスタ詳細から行い、登録先は `POST /api/v1/agent/register` とする。
- 専用の不透明Bearer・更新トークンとEd25519 JWS保有証明を使用する。管理画面JWTや外部APIキーとは分離する。
- ブローカーは未定との回答に基づき、MQTTは未構成として接続情報を返さず、バッチ命令・キャンセルの公開も停止する。
- 設定値・復旧期間・状態遷移の正本は[専用認証設計](../02_SystemDesign/認証/0005_agent_authentication.md)とする。

既存Machine詳細画面のset-state-in-effect違反とViteの500kB超チャンク警告は残る。
Checkstyleは既存・生成コードに違反が残り、ignoreFailures=trueのため終了コードだけで違反なしとは判断しない。新規Agentパッケージの本体・統合テストにCheckstyle違反はない。
Goから実APIへの確認は隔離したテスト環境のHTTPを使用。TLS拒否・リダイレクト拒否はhttptestのTLSサーバーとCLI入力チェックで別途確認しており、本番TLS終端の検証ではない。
Linuxはコンテナで権限・ロック・原子的保存を含むテストを実行した。macOSはクロスコンパイルまでであり、実機でのサービス・権限動作確認は今後必要。

## 導入条件・残課題

1. 本番DBへV22を適用し、専用32バイト乱数のAGENT_RESPONSE_ENCRYPTION_KEYとHTTPS終端を構成する。本作業では本番適用しない。
2. 古い実行要求の登録世代は補完しない。再実行が必要な場合、登録後に新しい実行IDで明示的に作成する。
3. MQTTの認証・ACL・接続失効・登録世代別の配信を実装する。同日の追加決定でEclipse Mosquittoを採用した（下記参照）。設定だけで配信停止を解除しない。
4. 常駐サービス登録、定期トークン更新、監視報告、実行ループ、OS別インストーラーは別工程。
5. 失効しても既に端末で動作中のプロセスは自動停止しない。キャンセル・停止確認は別契約である。

検証用バックエンド・Vite・ブラウザーは終了した。検証DBも停止し、本番環境や既存コンテナには変更していない。Git差分の空白チェックは対象5リポジトリで成功。

最終結合テストでは、WindowsのGo Agentから実バックエンドへ登録し、Mosquitto接続、OSコマンド実行、

バックエンド側でも他端末トピック拒否・Client ID偽装拒否・無効化後の切断を実ブローカーで確認した。
