## 車検期限管理の仕様整理

車両管理の主目的を車検切れ防止とし、Phase 1の要件・基本設計・画面設計を整理した。

### 確定事項

| 項目 | 決定内容 |
| --- | --- |
| 管理目的 | 車検有効期間満了日の管理と期限通知を中心とする |
| 個人情報 | 所有者・使用者の氏名および住所は保存しない |
| 取込形式 | テキストPDF、スキャンPDF、JPEG、JPG、PNGを対象として実装済み |
| 取込上限 | 1ファイル10 MiB、PDF 10ページ。署名と拡張子を照合する |
| 自動登録 | 行わず、解析結果の確認・修正後に登録する |
| 原本 | 設定可能な絶対一時ルートへUUID参照名で保存し、登録、取消、解析失敗、期限超過時に削除する |
| 保持期間 | 確認待ちは既定24時間。毎時15分の回収処理で期限切れ化し、終端状態の削除を再試行する |
| 閲覧権限 | ADMIN、OPERATOR、USERに許可する |
| 更新権限 | ADMINとOPERATORに許可し、USERは閲覧専用とする |
| 削除権限 | ADMINだけに許可する方針とする |
| 実装言語 | 業務処理、認可、一時ファイル管理、DB登録、監査はJava・Spring Bootで実装する |
| OCR共通化 | PDFテキスト抽出とOCRをバックエンド共通部品とし、車検証固有の項目解析を車両管理側に分離する |
| OCR実装 | PDFBoxによるPDFテキスト抽出と、Javaからシェルを介さず呼び出すTesseract CLIを採用 |
| 精度改善 | OCRエンジン追加より先に、画像前処理、文字領域の切出し、Tesseractの設定・学習データを改善する |
| 供給元方針 | 中国企業・中国系組織が主要な開発・保守・配布主体となるライブラリ、モデル、サービスは原則採用しない |
| 除外候補 | PaddleOCRおよびPaddlePaddleを採用候補から除外する |
| 外部送信 | 車検証原本を外部クラウドOCRへ送信しない |
| 原本の管理責任 | 車両管理の取込処理が一時ファイルを所有し、全終了経路で削除する |
