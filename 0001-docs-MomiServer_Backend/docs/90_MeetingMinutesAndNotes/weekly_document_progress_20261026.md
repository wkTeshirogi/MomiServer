# BE定数パッケージ統一・作業メモ 2026/10/26

## サマリ

BEの定数定義ファイルを、カテゴリ直下のconstantsパッケージへ統一した。
配置と参照のみを整理し、API、定数値、DB、認証・通知の業務仕様は変更しない。

## 決定事項

| No | 内容 |
| --- | --- |
| 1 | 定数定義は必ずベースパッケージ直下のカテゴリ.constantsに配置する |
| 2 | agent・batch・external・item・status・tools・user・vehicleは各カテゴリ、全体共通はcommon.constantsを使用する |
| 3 | service・config等に定数定義ファイルを残さず、既存の用途別クラス名と責務を維持する |
| 4 | 別パッケージから参照するために必要な公開範囲だけを与え、公開コレクションは不変にする |
| 5 | Enum、Logger、SecureRandom、jOOQメタデータ、生成コードを機械的に移動しない |

## 作業内容

| 区分 | 内容 |
| --- | --- |
| 配置 | 定数定義48ファイル中47ファイルを移動。既存のSecurityAuthorityConstantsは配置を維持 |
| 参照 | 本体とテストのimport・static importを更新 |
| 互換性 | APIログの属性名は旧パッケージ名に由来する既存値を維持し、配置変更に連動させない |
| 不変性 | 設計書生成の対象一覧と一時ファイルの権限セットを書換え不可にし、内容と順序・権限は維持 |
| 保守 | BEのAGENTS・READMEへ配置規則を記録。トークンハッシュ設計書の定数配置説明を更新 |
| 回帰防止 | ConstantDefinitionPolicyTestで物理配置・宣言パッケージ・生成禁止・公開値の不変性・既存値を確認 |

## 追記: セキュリティ共通設定とログイン制御

### セキュリティ設定の決定事項

利用者回答に基づき、セキュリティ共通設定は`application.yaml`だけで管理する。
画面から設定を保存する方式は採用せず、共通設定画面はADMIN向けの参照専用とする。

| 項目 | 確定した方針 |
| --- | --- |
| 設定管理 | `application.yaml`。設定保存用のDBテーブルは新設しない |
| 画面権限 | ADMINのみ閲覧可。編集・保存操作は設けない |
| 反映時期 | 設定ファイルの変更後、バックエンド再起動で反映する |
| トークン期限 | 次回発行・更新するトークンに適用する。発行済みの期限は書き換えない |
| 既存認証基盤 | 認証セッション等の既存DB利用は維持する。設定保存用DBを追加しない方針とは区別する |
| 秘密情報 | JWT署名鍵・APIキー原文等は参照画面に表示しない。既存の環境変数・secret管理を維持する |
| 対象境界 | Webユーザーと既存API制限を対象とし、Agent認証の期限設定とは分離する |

画面からの設定保存、保存直後の動的反映、設定保存APIの同時更新制御は対象外とする。
認証そのものを無効化する共通スイッチは設けない。IoTレート制限のOFFは認証のOFFを意味しない。

### 設定項目

| 項目 | 初期値 | 補足 |
| --- | --- | --- |
| Web Access Token有効期限 | 24時間 | 現行値を維持する |
| Web Refresh Token有効期限 | 24時間 | 発行・更新時からの期限。ログインからの絶対継続上限とは別 |
| IoT APIレート制限 | OFF | 既存Gatewayの制限対象・単位を維持する |
| IoT API許可回数 | 60回/分 | レート制限有効時に適用する |
| 外部在庫API許可回数 | キーごとに1,000回/時 | 全キー共通の上限。現状のJava定数を設定化する作業が必要 |
| ログイン失敗の許容回数 | 5回 | 連続失敗を対象とする |
| 一時ロック時間 | 15分 | ロック開始時から計算する |

既存の設定値を維持する初期値と、一般的なセキュリティ推奨値は同一視しない。
設定キー名・入力範囲・参照画面の具体的な表示単位は実装時に整理する。

### ログイン制御

| 項目 | 確定した仕様 |
| --- | --- |
| 対象 | Webユーザーのアカウント単位。Agent認証は対象外 |
| 1回目から5回目の失敗 | 通常の認証失敗として扱い、連続失敗回数を加算する |
| 6回目の試行 | パスワード照合前に拒否し、一時ロックを開始する。正しいパスワードでもこの試行は許可しない |
| ロック期間 | 初期値15分。ロック中の試行でも解除予定時刻を延長しない |
| ログイン成功 | 連続失敗回数をリセットする |
| 期間終了 | 一時ロックを解除し、連続失敗回数をリセットする |
| 管理者通知 | ロック開始時に1回。ロック中の試行ごとには通知しない |
| 配信先 | 既存通知基盤で管理者ユーザー宛てに配信し、一般ユーザーには表示しない |
| 管理状態 | `BAN_USER`等の既存ロール・管理状態は変更せず、一時ロックとは分離する |

通知・ログへパスワードやトークン原文を記録しない。
通知チャネルと配信先は既存通知基盤の設定に従い、通知の有効・無効とログイン拒否の判定は分離する。

### 保持方式の追加決定

- 当初はメモリ保持案が確認待ちだったが、同日の追加回答で「再起動後もロック状態を維持したい」と確定した。
- 設定値は`application.yaml`、失敗回数・ロック解除予定日時は既存の`m_users`へ保存する。設定保存用DBは新設しない。
- 詳細な実装契約は[セキュリティ共通設定設計](../11_SecurityDesign/0007_security_common_settings.md)を正本とする。
