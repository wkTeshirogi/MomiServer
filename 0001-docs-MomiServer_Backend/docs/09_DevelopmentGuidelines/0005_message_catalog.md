# 共通メッセージ管理

## 概要

バックエンドとフロントエンドで表示文言や通知文言が重複しないように、共通メッセージカタログを使用する。

バックエンドの `message-catalog/messages.ja.json` を正とし、フロントエンド側は同じメッセージキーを使って画面表示を行う。

## 対象

| 分類 | 管理対象 |
| --- | --- |
| 通知 | ブラウザ通知、Discord通知のタイトルと本文 |
| 入力チェック | フロントエンドのバリデーション文言 |
| エラー表示 | ユーザーに表示するAPIエラー文言 |

## 命名規則

メッセージキーは、機能、用途、詳細の順にドット区切りで定義する。

例:

- `inventory.low.title`
- `validation.inventory.itemRequired`
- `error.inventory.notFound`

## 実装ルール

- 画面やサービスに日本語文言を直接埋め込まず、原則としてメッセージカタログから取得する。
- ユーザーに表示しない内部ログや例外詳細は、ユーザー表示用メッセージとは分離する。
- 動的値は `{itemId}` のような名前付きプレースホルダーで表現する。
- TypeScript側は `erasableSyntaxOnly` を考慮し、TypeScript enum ではなく `as const` オブジェクトでコードを表現する。
- メッセージ追加時は、バックエンドのJSON、バックエンドのメッセージコード、フロントエンドのメッセージカタログを同期する。

## 画面内の処理結果通知

共通の `NotificationBanner` は、文言の取得とは別に通知の表示・閉じる操作を担当する。

| 項目 | 実装上の扱い |
| --- | --- |
| 種別 | error・success・warning・info |
| 読み上げ | error・warningはalert、それ以外はstatus。aria-atomicを有効にする |
| 閉じる | 非表示にし、指定された場合は呼び出し元へ通知する |
| 再表示 | 種別または本文が変わると新しい通知として表示。同じ内容の親再描画では再表示しない |
| 自動スクロール | autoScroll指定時のみ実行。既定は無効 |

根拠はフロントエンドの `src/components/ui/notification-banner.tsx`。
配置は呼び出し側が決める。この部品単体でヘッダー直下へ移動するものではない。

## カタログの同期

バックエンドのメッセージJSONを更新した後、以下を実行してフロントエンドのカタログを同期する。

```text
node tools/messages/generate-message-catalog.mjs
```

同期後は、バックエンドとフロントエンドの参照箇所を確認し、ビルドまたはテストで未定義キーがないことを確認する。
