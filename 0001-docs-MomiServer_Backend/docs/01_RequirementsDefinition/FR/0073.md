# バッチ実行ファイルアップロード

> 状態: 旧API案・未実装。以下の `/upload/{category}` とその入出力は現行APIでは提供していない。
> 再設計時にはAgent専用Bearerと実行要求の端末・登録世代の認可を適用する。

## 機能ID

FR-0073

## 機能名

バッチ実行ファイルアップロード

## 概要

Agent がバッチ処理で発生した実行ログおよび成果物を Momi Server へアップロードできるようにする。
アップロードされたファイルはバッチ実行単位で管理し、実行結果確認、障害調査、成果物取得に利用する。

## 関連サービス

- バッチ管理
- Agent 連携
- ファイル管理

## 詳細要件

### 1. カテゴリ別アップロード

#### 詳細説明

Agent はアップロード先を `/upload/{category}` の形式で指定し、実行ログと成果物をカテゴリで切り分けて送信できること。

#### 入力項目

| 項目名 | 必須 | 内容 |
| --- | --- | --- |
| category | 必須 | アップロードカテゴリ。`log` または `artifact` を基本とする |
| execution_id | 必須 | バッチ実行要求 UUID |
| file_name | 必須 | アップロードするファイル名 |
| content_type | 任意 | ファイルの Content-Type |
| checksum_sha256 | 任意 | ファイル内容の SHA-256 |
| file | 必須 | アップロード対象ファイル |

#### 処理内容

- アップロードカテゴリを検証する。
- 対象バッチ実行要求と Agent の紐づきを検証する。
- ファイル本体をサーバー側ストレージへ保存する。
- ファイルサイズ、ハッシュ値、保存先、アップロード状態を記録する。

#### 正常系

- 実行ログはログカテゴリとして保存される。
- 成果物は成果物カテゴリとして保存される。
- 保存したファイルはバッチ実行詳細から参照できる。

#### 異常系

| 条件 | 動作 |
| --- | --- |
| 未対応カテゴリが指定された | 入力エラーとして扱う |
| バッチ実行要求が存在しない | リソース未検出エラーとして扱う |
| Agent が対象実行要求に紐づかない | 権限エラーとして扱う |
| ファイル保存に失敗した | アップロード失敗として記録する |

## API仕様

| 項目 | 内容 |
| --- | --- |
| Method | POST |
| Path | `/api/v1/agent/upload/{category}` |
| 認証 | 旧案: Gateway APIキー。現行方式では不可、再設計が必要 |

## 非機能要件

| 項目 | 内容 |
| --- | --- |
| セキュリティ | Agent 認証と実行要求単位のアクセス制御を行う |

| 監査 | アップロード日時、Agent、カテゴリ、ファイル情報を記録する |
