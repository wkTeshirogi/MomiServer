# サービス単位のアクセス制御

| 項目 | 内容 |
| --- | --- |
| 機能ID | FR-0007 |
| カテゴリ | ユーザー管理 |
| 優先度 | 中 |

## 概要

画面、API、操作および外部システム導線の利用可否を、ユーザーのロールに基づいて制御する。
Phase 1ではユーザー個人単位の許可上書きは行わず、ロールを認可の正本とする。

## ロール

| ロール | 用途 | 権限順位 |
| --- | --- | --- |
| `ADMIN` | システム設定、マスタ管理、全運用操作 | 999 |
| `OPERATOR` | 日常運用、マシン・サービス監視 | 100 |
| `USER` | 一般利用、サービス参照、在庫、通知 | 10 |
| `BAN_USER` | 利用禁止 | 0 |

通常ロールの権限階層は `ADMIN > OPERATOR > USER` とする。
`BAN_USER` は階層比較の対象外とし、常に認証・認可を拒否する。

## 機能要件

- Web画面およびWeb APIのアクセス可否はロール単位で定義すること
- Phase 1ではユーザー単位のアクセス許可・拒否上書きを設けないこと
- 未認証の保護APIアクセスは401、認証済みで権限不足の場合は403を返すこと
- 存在しないAPIまたはリソースは、認可判定後に404を返すこと
- フロントエンドは権限のないルート、メニュー、操作ボタンを表示または利用させないこと
- フロントエンドの表示制御だけに依存せず、バックエンドを認可判定の正本とすること
- `BAN_USER` はログイン、トークン更新、保存済み認証情報の復元、既存トークンによるAPIアクセスを拒否すること
- ユーザーを `BAN_USER` へ変更した場合、当該ユーザーの有効な認証セッションを失効すること
- バッチ定義の `required_role` は権限階層で判定し、必要ロール以上のユーザーに手動実行と実行詳細参照を許可すること
- バッチ実行の取消は `ADMIN` のみに許可すること
- バッチ定義の `required_role` が未設定または未知の場合は拒否すること。ただし `ADMIN` の管理者上書きは維持すること
- 通知はロールによる画面可否に加えて、本人宛てデータと通知リンク先の閲覧範囲で絞り込むこと
- Agent認証およびIoT Gateway認証はWebユーザーのロール認可と分離すること

画面、操作および外部システム導線の詳細は[認可設計](../../11_SecurityDesign/0002_authorization.md)を参照する。

## 非機能要件

- ロール変更は次回リクエストから反映すること
- 認証・認可の拒否理由から、アカウントの存在や利用禁止状態を第三者が判別できないこと
- 未知のロールまたは権限値は許可側へ補正せず、拒否側へ倒すこと
- 画面または操作を追加した場合は、権限表、バックエンド認可、フロントエンド制御、回帰テストを同時に更新すること
