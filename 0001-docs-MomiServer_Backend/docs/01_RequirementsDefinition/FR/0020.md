# タスク状態管理（バッチ実行要求）

| 項目 | 内容 |
| --- | --- |
| 機能ID | FR-0020 |
| カテゴリ | タスク管理 |
| 優先度 | 中 |

## 概要

[FR-0019](0019.md)で定義するバッチ実行要求の状態遷移を管理する。
人向けToDoの`TODO`・`IN_PROGRESS`・`DONE`はPhase 1対象外とする。

## 機能要件

- 状態値は英語とし、以下の現行バッチ状態を使用する。
- Agentの報告と確認状況に基づいて状態を更新し、状態変化時の日時を記録する。
- 取消要求の受付と取消完了を区別し、停止確認前に`cancelled`へ確定しない。
- 結果不明の実行は`running`を維持し、自動再実行しない。
- 定義の有効状態・削除状態と、実行要求の状態を混同しない。

| 状態 | 意味 |
| --- | --- |
| `queued` | 要求作成済みで配信待ち |
| `dispatched` | Agentへ通知済み。実行開始の確認とは区別 |
| `running` | 実行中。結果不明の場合も維持 |
| `success` | 正常終了 |
| `failed` | 異常終了 |
| `timeout` | タイムアウトによる停止を確認済み |
| `cancelled` | 取消による未開始・停止を確認済み |
| `expired` | 未開始のまま開始期限を過ぎたことを確認済み |

## 非機能要件

- 不正な状態遷移はAPIレベルで拒否すること。
- 定義の無効化・削除と要求の取消・終了確認の関係は[FR-0019](0019.md)に従う。
- 現行の実行状態管理と、新たに合意した定義無効化への取消連動の実装状況は分けて判定する。
