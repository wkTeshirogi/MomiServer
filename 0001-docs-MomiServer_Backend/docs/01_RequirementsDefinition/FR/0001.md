# ユーザーの作成・更新・削除

## 機能ID

FR-0001

## 機能名

ユーザー管理機能

## 概要

システム利用者のユーザー情報を管理する機能を提供する。管理者ユーザーはユーザーの作成・更新・削除を実施できる。

## 関連サービス

- Auth Service

## 詳細要件

### 1. ユーザー作成

## ユーザー作成の概要

新規ユーザーを登録する。

## 入力項目

| 項目名 | 必須 | 内容 |
| --- | --- | --- |
| ユーザー名 | ○ | ログイン時に使用する名称 |
| メールアドレス | ○ | 一意であること |
| パスワード | ○ | 規定文字数以上 |
| ロール | ○ | 管理者 / 一般ユーザー |

## ユーザー作成の処理内容

- 入力値バリデーションを行う
- メールアドレス重複確認を行う
- パスワードをハッシュ化する
- DBへ保存する

## ユーザー作成の正常系

- ユーザー情報が登録される
- ユーザー一覧へ反映される

## ユーザー作成の異常系

| 条件 | 動作 |
| --- | --- |
| メールアドレス重複 | エラー返却 |
| 必須項目不足 | エラー返却 |
| DB障害 | ログ記録後エラー返却 |

### 2. ユーザー更新

## ユーザー更新の概要

既存ユーザー情報を更新する。

## 更新可能項目

- ユーザー名
- パスワード
- ロール
- 有効 / 無効状態

## ユーザー更新の処理内容

- 対象ユーザー存在確認
- 更新権限確認
- 変更内容の保存

## ユーザー更新の正常系

- 更新内容が反映される

## ユーザー更新の異常系

| 条件 | 動作 |
| --- | --- |
| 対象ユーザー不存在 | エラー返却 |
| 権限不足 | エラー返却 |

### 3. ユーザー削除

## ユーザー削除の概要

既存ユーザーを削除する。

## ユーザー削除の処理内容

- 対象ユーザー存在確認
- 削除権限確認
- マスタ共通方針に従い、ユーザーのステータスを削除扱いの状態へ更新する
- 削除専用フラグや物理削除では管理しない

## ユーザー削除の正常系

- ユーザーのステータスが削除扱いの状態へ更新される

## ユーザー削除の異常系

| 条件 | 動作 |
| --- | --- |
| 対象ユーザー不存在 | エラー返却 |
| 自身の管理者アカウント削除 | エラー返却 |

## API仕様

### ユーザー作成API

| 項目 | 内容 |
| --- | --- |
| Method | POST |
| Path | /api/users |
| 認証 | 必須 |

### ユーザー更新API

| 項目 | 内容 |
| --- | --- |
| Method | PUT |
| Path | /api/users/{id} |
| 認証 | 必須 |

### ユーザー削除API

| 項目 | 内容 |
| --- | --- |
| Method | DELETE |
| Path | /api/users/{id} |
| 認証 | 必須 |

## 非機能要件

| 項目 | 内容 |
| --- | --- |
| セキュリティ | パスワードはbcryptでハッシュ化 |
| 可用性 | API応答時間は3秒以内 |
| 監査 | 作成・更新・削除ログを記録 |
| 権限管理 | 管理者のみ操作可能 |

## 備考

- マスタデータの削除は全て物理削除ではなく、ステータス更新による論理削除とする
- マスタデータの削除状態を `delete_flag`、`deleted`、`is_deleted` などの削除専用フラグでは管理しない
- JWT認証を利用する
- 操作ログは監査ログへ送信する
