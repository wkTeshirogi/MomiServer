# 車検期限管理

## 機能ID

FR-0076

## 機能名

車検期限管理

## 概要

車両の車検有効期間満了日を管理し、車検切れを防止する。
初期実装では手動登録・閲覧・編集・管理終了・期限履歴に加え、自動車検査証記録事項のPDFまたは撮影画像からの確認付き取込を提供する。
期限通知は日次処理と起動時の補完処理で提供する。

## 関連サービス

- 車両管理
- 通知基盤
- ファイル解析

## 実装範囲

| 区分 | 対象 |
| --- | --- |
| 初期実装済み | 車両一覧・詳細、手動登録・編集、管理終了、車検期限履歴、期限状態判定、ロール認可、PDF・画像取込、共通OCR、解析結果確認、期限通知 |
| Phase 1追加実装済み | 満了日当日の独立通知、保存成功後の期限判定 |
| 通知追加の対象外 | 期限更新による旧通知の自動解消、車両別の期限通知ON/OFF |

## 詳細要件

### 1. 車両情報管理

#### 車両情報管理の目的

車検期限管理に必要な車両識別情報と有効期間満了日を管理する。
所有者および使用者の氏名・住所は管理対象に含めない。

#### 入力項目

| 項目名 | 必須 | 内容 |
| --- | --- | --- |
| display_name | 必須 | 画面上で車両を識別する名称 |
| registration_number | 必須 | 自動車登録番号または車両番号 |
| chassis_number | 必須 | 車台番号。重複判定に使用する |
| vehicle_identification_code | 任意 | 電子車検証の車両識別符号 |
| vehicle_name | 必須 | 車名 |
| model_code | 任意 | 型式 |
| first_registration_month | 任意 | 初度登録年月または初度検査年月 |
| inspection_expiry_date | 必須 | 自動車検査証の有効期間満了日 |
| issued_date | 任意 | 車検証の交付年月日 |
| usage_category | 任意 | 自家用・事業用の別 |
| purpose | 任意 | 用途 |
| status | 必須 | `VALID`、`DUE_SOON`、`URGENT`、`EXPIRED`、`UNKNOWN`、`ARCHIVED` |
| notes | 任意 | 車両に関する任意メモ |

#### 車両情報の処理

- 車検有効期間満了日は車両登録時の必須項目とする。
- 車検状態は満了日と基準日から判定する。
- 車検状態は満了日まで30日以内を`DUE_SOON`、7日以内を`URGENT`、満了日経過を`EXPIRED`とする。
- 初期実装では車台番号、車両識別符号、登録番号と初度登録年月で重複候補を判定する。
- 取込原本およびファイルハッシュは永続保存せず、車台番号、車両識別符号、登録番号と初度登録年月で重複候補を判定する。
- 車検期限を更新した場合は、更新前後の期限、更新者、更新日時を履歴へ記録する。
- 登録済み車両の詳細に車検更新操作を提供し、車両情報全体の保存と分離する。
- 年数選択による満了日候補の計算、入力項目と競合時の扱いは[画面設計](../../06_UserInterfaceDesign/3008_vehicle_management.md)に従う。
- 状態値は英語で保存し、日本語への変換は表示側で行う。

#### 車両情報の正常系

- ADMINおよびOPERATORは車両を登録・編集できる。
- USERは登録済み車両と車検期限を閲覧できる。
- 車検期限が近い車両を優先して一覧表示できる。

#### 車両情報の異常系

| 条件 | 動作 |
| --- | --- |
| 車検有効期間満了日が未入力 | 登録不可として入力エラーを表示する |
| 重複候補が存在する | 新規登録せず、既存車両との差分確認へ誘導する |
| USERが更新を要求する | HTTP 403として拒否する |

### 2. 車検証ファイル取込（実装済み）

#### ファイル取込の目的

取込機能の実装フェーズではテキストPDF、スキャンPDF、JPEG、JPG、PNGを受け付ける。
解析結果を自動登録せず、確認・修正画面を経由して登録する。

#### ファイル取込の処理

- PDFにテキストが含まれる場合はテキスト抽出を優先する。
- テキスト抽出できないPDFと画像にはOCRを使用する。
- PDFテキスト抽出とOCRは、業務非依存の共通文書文字抽出機能を使用する。
- 車検証固有の項目対応付けと検証は車両管理機能で行う。
- 車台番号と車検有効期間満了日は必ず確認対象として強調する。
- 氏名・住所を読み取った場合でもレスポンス、DB、アプリケーションログへ保存しない。
- 原本は確認中のみ一時保存し、登録完了、キャンセル、解析失敗または保管期限超過時に削除する。
- 登録後は候補値、解析方式、解析結果状態、取込日時のみを保持し、原本と抽出全文は保持しない。
- OCRはサーバーに設定したローカルTesseract CLIを利用する外部前提とする。実行ファイルまたは`jpn+eng`言語データが使えない場合は、原本を削除し、利用者へ日本語の設定確認・手動登録案内を返す。

#### ファイル取込の異常系

| 条件 | 動作 |
| --- | --- |
| 未対応形式 | 受付を拒否して対応形式を表示する |
| 暗号化またはパスワード付きPDF | 解析対象外としてエラーを表示する |
| 満了日を抽出できない | 手動入力を要求し、未入力のまま登録させない |
| 必須項目を抽出できない | 該当項目を警告表示して手動入力を要求する |
| 解析処理が失敗する | エラーを表示し、一時ファイルを削除する |

### 3. 車検期限通知（既存実装・追加要件）

#### 車検期限通知の目的

日次処理で車検期限を確認し、既存の通知基盤を使用して期限接近または期限超過を通知する。

#### 車検期限通知の処理

- 車両ID、満了日、通知タイミングを冪等キーとして重複通知を防止する。
- 満了日が更新された場合は新しい通知周期として扱う。
- 通知種別は`vehicle_inspection_expiry`とする。
- 現行実装は満了日当日の独立通知を含む5段階。各段階につき1回だけ通知する。
- 起動時や停止後の再開時は現在該当する段階だけを補完する。判定・重要度・配信の詳細は[基本設計](../../02_SystemDesign/車両管理/0001_vehicle_inspection_management.md)を参照する。

#### 2026/10/26見直し後の追加要件（実装済み）

- 通知時期は全車両共通とし、車両別に通知日数や配信先を持たせない。
- 満了日当日の独立通知と保存成功後の判定を追加対象とし、2026/10/24の追加要件から対象範囲を見直す。
- 登録・満了日更新の保存成功後にも判定し、通知期間内なら現在該当する未通知段階を通知する。
- 満了日翌日以降の期限切れ通知は原則1回とし、毎日繰り返さない。
- 期限更新だけを理由とする旧通知の自動解消は行わない。既存の既読・非表示・保持期間の扱いを維持する。
- 車両別の期限通知ON/OFFは追加しない。通知全体設定、通知ルート、ユーザー別受信設定を利用する。
- 配信先には既存の通知ルート設定を使用する。配信先を後から設定した場合の再通知とDiscord送信失敗時の再送は行わない。
- V39で当日段階`DUE_TODAY`を追加し、保存コミット後の判定を実装した。旧通知の自動解消と車両別ON/OFFは追加しない。

## 権限

| 操作 | ADMIN | OPERATOR | USER |
| --- | --- | --- | --- |
| 一覧・詳細閲覧 | 可 | 可 | 可 |
| PDF・画像取込 | 可 | 可 | 不可 |
| 新規登録・編集 | 可 | 可 | 不可 |
| 管理終了・削除 | 可 | 不可 | 不可 |

## 非機能要件

| 項目 | 内容 |
| --- | --- |
| セキュリティ | 所有者・使用者の氏名・住所を保存せず、原本へのアクセスを確認処理中だけに限定する |
| 一時ファイル | 正常・異常を問わず削除契機を設け、確認放置時は期限切れ削除する |
| 監査 | 車両登録、期限更新、管理終了、ファイル取込の実行者と日時を記録する |
| 通知 | 同一車両・満了日・通知タイミングで重複通知しない |
| 可用性 | ファイル解析に失敗しても手動登録を継続できる |
