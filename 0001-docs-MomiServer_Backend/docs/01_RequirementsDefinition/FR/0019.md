# タスク作成・更新・削除

| 項目 | 内容 |
| --- | --- |
| 機能ID | FR-0019 |
| カテゴリ | タスク管理 |
| 優先度 | 中 |

## 概要

Phase 1のタスクは、Agentで実行するバッチ処理を指す。
担当者・期限を持つ人向けの汎用ToDo管理は対象外とする。
2026/10/09の合意に基づく要件であり、以下の全項目が実装済みという意味ではない。

## 機能要件

### 管理単位と作成

- バッチ定義は処理内容、スケジュールは実行予定、実行要求は1回の実行として分離する。
- バッチ定義の名称・説明・実行設定・優先度・有効状態等を登録・更新できること。
- 定義登録と実行要求作成は別操作とし、定義を登録しただけでは実行しないこと。
- 現行のバッチ管理APIを基礎とし、汎用の`/api/tasks`を新設する要件にはしない。

### 定義更新の反映範囲

- 定義更新は、更新後に新規作成する実行要求にだけ反映する。
- 作成済み・未開始、実行中、完了済みの要求と履歴は書き換えない。
- 当日・翌日分を事前作成するため、日中の更新は作成済みの翌日分にも自動反映しない。
- 作成済みの未開始要求を変更する場合は、明示的な取消・再作成操作として分離する。
- 取消・再作成は同一実行IDの再利用や重複実行を許可する意味ではない。

### 無効化と論理削除

- 無効化すると、新しい実行要求の作成を停止する。
- 作成済み・未開始の要求は取消対象とする。Agentへ配信済みの場合は未開始・停止の確認を待つ。
- 無効化と開始が競合した場合も、確認なしで取消完了にはしない。
- 実行中の要求は無効化だけでは停止しない。停止する場合は別途取消操作を行う。
- 論理削除は、先に無効化し、未完了要求がなくなってから許可する。
- 結果不明の実行は実行中のまま扱い、終了確認まで論理削除の条件を満たしたとみなさない。
- 削除は英語のステータス値で管理する。`enabled`は有効・無効専用とし、削除フラグには流用しない。
- 物理削除・専用DELETE APIは設けない。完了済み要求・履歴・参照中の添付を保持する。

### 添付・共通設定の範囲

添付の即時確定、実行要求単位の参照固定、Agentへの配布・検証、共通設定の適用は
[ファイル転送詳細設計](../../02_SystemDesign/バッチ管理/Details/0005_batch_file_transfer_detail_design.md)に従う。
旧転送UUID・専用完了通知方式、成果物ファイルのアップロード、
バックエンドの未参照添付・一時ファイルの自動回収はPhase 1の必須条件に含めない。
既存APIの即時撤去は行わず、現行契約と旧設計案を区別する。

## 非機能要件

- バッチ定義は更新番号`version`を持ち、編集・有効／無効切替・論理削除に共通で楽観的ロックを適用する。
- 保存時は画面で取得した更新番号をDBと照合し、内容更新と更新番号加算を原子的に行う。
- 更新競合はHTTP 409で拒否し、古い画面からの上書きや意図しない再有効化を防止する。
- 画面では入力を保持して上部に競合エラーを表示する。最新データの再取得は利用者が選択する。

## Phase 1完了判定

次の実装と回帰確認が完了するまで「一部実装」とする。

- 定義の登録・更新・無効化・論理削除と、作成済み要求に対する反映範囲が要件どおりであること。
- 未開始取消と開始の競合、実行中・結果不明時の削除拒否を確認できること。
- 更新競合の409、入力保持、利用者による再取得をAPI・画面で確認できること。
- 添付配布・共通設定・結果確認まで、既存契約を維持した結合確認が成功すること。
