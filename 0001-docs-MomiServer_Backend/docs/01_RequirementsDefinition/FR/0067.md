# 認証処理

| 項目 | 内容 |
| --- | --- |
| 機能ID | FR-0067 |
| カテゴリ | API Gateway |
| 優先度 | 高 |

## 概要

API入口で利用元に応じた認証（管理ユーザーJWT・Agent専用Bearer・IoT APIキー）を行う機能。

## 機能要件

- Webユーザー向けAPIはJWTトークンで認証できること
- 通常のAgent APIはAgent専用Bearerで認証し、管理ユーザーJWTや外部APIキーを受け付けないこと
- Agentの登録・challenge・更新は専用認証手順で扱うこと
- 自作IoT機器向けAPIはGatewayのAPIキーで認証できること
- 認証失敗時は401を返し、バックエンドサービスへリクエストを転送しないこと
- 認証済みの利用元をSecurityContextに設定し、後続のControllerで認可できること
- APIキー関連設定は `.env` で管理すること

## 非機能要件

Agentの登録・更新・端末単位認可は[Agent専用認証設計](../../02_SystemDesign/認証/0005_agent_authentication.md)を参照する。

- 認証処理50ms以内は性能目標とし、Phase 1の機能テストでは性能保証の判定を行わない。

## Phase 1完了条件

- 実DBとSecurityFilterChainを使用し、Web JWT、Agent専用Bearer、IoT APIキーが別の認証方式の代用にならないことを確認する。
- Web API・画面の利用可否はロール単位で判定する。ユーザー個人単位の許可設定は対象外とする。
- 未認証は401、WebユーザーがAgent専用APIを利用する場合は403となることを確認する。
- [Gatewayテスト設計](../../08_TestDesign/0005_gateway_test.md)に定義した認証境界の回帰テストが成功する。
