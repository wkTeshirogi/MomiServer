# レート制限

| 項目 | 内容 |
| --- | --- |
| 機能ID | FR-0068 |
| カテゴリ | API Gateway |
| 優先度 | 中 |

## 概要

APIへの過剰なリクエストを制限し、システムを保護する機能。

現行のGateway固定ウィンドウ制限はIoT経路のみを対象とする。Agent登録・challenge・更新の要求回数は専用認証基盤でDB管理し、通常のAgent APIにはGateway制限を適用しない。

Phase 1ではIoTのAPIキーまたはIP単位の固定ウィンドウ制限を対象とする。
Web API・画面の利用可否はロール単位の認可で管理し、ユーザー個人単位のアクセス許可・レート制限は設けない。

## 機能要件

- IoTのAPIキー単位、APIキー認証を無効にした場合は送信元IP単位でリクエスト数を制限できること
- 制限を超えたリクエストには429（Too Many Requests）を返すこと
- レスポンスヘッダーに `X-RateLimit-Limit` と `X-RateLimit-Remaining` を含め、超過時に `Retry-After` を返すこと
- レート制限の有効化および標準上限値は `.env` で管理すること

## 非機能要件

- 初期実装ではアプリケーション内メモリでの管理を許容する
- 分散環境が必要になった場合はRedis管理へ拡張すること

## Phase 1完了条件

- IoTの設定上限までControllerへ到達し、超過時に429と制限ヘッダーを返す自動テストが成功する。
- Gatewayレート制限がWeb JWT APIと通常のAgent APIに適用されないことを確認する。
- キー・IP単位、ウィンドウ切替、有効・無効設定の単体テストが成功する。
- エンドポイント別・ロール別のレート上限、リセット日時ヘッダー、分散管理は必要性が生じた時点で仕様を更新し、Phase 1の完了条件には含めない。

検証方法は[Gatewayテスト設計](../../08_TestDesign/0005_gateway_test.md)を参照する。
