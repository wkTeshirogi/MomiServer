# リクエストルーティング

| 項目 | 内容 |
| --- | --- |
| 機能ID | FR-0066 |
| カテゴリ | API Gateway |
| 優先度 | 高 |

## 概要

外部からのリクエストをパスとメソッドに応じて適切なAPIへ振り分ける機能。
現行構成は単一Spring Bootアプリケーション内のControllerへ振り分ける。マイクロサービスへのプロキシ転送は未実装の将来構想とする。

## 機能要件

- URLパス・メソッドに基づいてリクエストを各サービスへルーティングすること
- Gateway入口制御の設定は環境変数（運用時は `.env` 等）で管理すること
- ルーティング先サービスが不明な場合は404を返すこと

## Phase 1の認可方針と完了条件

- Web API・画面の利用可否は `ADMIN`、`OPERATOR`、`USER` のロール単位で制御する。ユーザー個人単位の許可設定は設けない。
- 画面・APIの追加や操作変更時に、対象ロール、バックエンド認可、フロントエンドの経路制御、回帰テストを更新する。
- Agentの端末・登録世代単位の認可と、通知の宛先・閲覧範囲の制御は維持する。
- 現行Controllerへの振り分け、存在しない経路の404、利用元別の認証境界を自動テストで確認する。
- マイクロサービスへのプロキシ転送はPhase 1の完了条件に含めない。

検証方法は[Gatewayテスト設計](../../08_TestDesign/0005_gateway_test.md)を参照する。

## 非機能要件

- 将来、独立したGatewayでルーティングする場合の目標値はオーバーヘッド10ms以内とする。現行構成での計測・保証値ではない。
