# バッチ管理 要件定義

## 目的

バッチ管理は、管理者がバッチ処理の定義、実行スケジュール、実行要求、実行履歴を管理し、対象Agentへ安全に実行指示を送信できるようにする機能である。

Phase 1のタスク作成・更新・削除は本機能を指す。人向けの汎用ToDo管理は対象外とする。
定義の更新・無効化・論理削除・更新競合と完了条件は[FR-0019](../FR/0019.md)に従う。
これらの仕様確定は実装完了を意味しない。

## 対象範囲

| 区分 | 内容 |
| --- | --- |
| バッチ定義管理 | バッチ名、実行種別、実行コマンド、作業ディレクトリ、ログ出力先、通知設定を管理する。 |
| バッチ定義パラメータ管理 | バッチ実行時に利用するパラメータをバッチ定義単位で管理する。 |
| バッチスケジュール管理 | バッチ定義、対象Agent、Cron式、実行期間、休日実行可否、優先度を管理する。 |
| 手動実行 | 管理者操作により指定したバッチ定義を対象Agentへ実行要求として登録する。 |
| スケジュール実行 | 有効な定義・スケジュールから日次で当日未作成分と翌日分を事前作成し、実行予定と要求を分離する。 |
| Agent連携 | MQTTで実行指示を通知し、AgentからHTTPで開始・完了通知を受け付ける。 |
| 実行履歴管理 | 実行結果、終了コード、実行時間、ログ参照情報を履歴として管理する。 |

## 対象外

| 区分 | 内容 |
| --- | --- |
| Agent導入 | Agent本体のインストール、OSサービス登録、端末側常駐管理は対象外とする。 |
| 実行ログ全文保存 | 実行ログの全文アップロードは対象外とし、ログ参照先または概要情報を管理する。 |
| Agent認証強化 | Agent専用Bearerと登録時の署名検証は実装済み。証明書認証などの追加方式は将来拡張とする。 |
| 汎用ToDo管理 | 担当者・期限を持つ人向けタスクはPhase 1対象外とする。 |
| 旧転送方式 | 使い切り転送UUIDと専用完了通知方式は将来案。既存APIの即時撤去は行わない。 |
| 成果物アップロード | CSV・ZIP等の成果物ファイル転送は後続対応とする。 |
| バックエンド実体回収 | 未参照添付・一時ファイルの自動回収は後続対応。Agent作業ディレクトリの回収とは分離する。 |

## 機能要件

| ID | 要件 | 内容 |
| --- | --- | --- |
| BFR-001 | バッチ定義一覧参照 | 登録済みのバッチ定義を一覧で参照できること。 |
| BFR-002 | バッチ定義詳細参照 | バッチ定義IDを指定して詳細を参照できること。 |
| BFR-003 | バッチ定義登録 | バッチ名、表示名、カテゴリ、実行種別、実行コマンド、ログ出力先を登録できること。 |
| BFR-004 | バッチ定義更新 | 既存のバッチ定義を更新できること。 |
| BFR-005 | バッチ定義パラメータ管理 | バッチ定義に紐づく実行パラメータを管理できること。 |
| BFR-006 | バッチスケジュール一覧参照 | 登録済みのバッチスケジュールを一覧で参照できること。 |
| BFR-007 | バッチスケジュール詳細参照 | バッチスケジュールIDを指定して詳細を参照できること。 |
| BFR-008 | バッチスケジュール登録 | バッチ定義、対象Agent、Cron式、実行期間、優先度を登録できること。 |
| BFR-009 | バッチスケジュール更新 | 既存のバッチスケジュールを更新できること。 |
| BFR-010 | 手動実行要求作成 | 管理者操作によりバッチ実行要求を作成できること。 |
| BFR-011 | スケジュール実行要求作成 | Cron式に該当するスケジュールからバッチ実行要求を作成できること。 |
| BFR-012 | MQTT実行通知 | 対象AgentのMQTTトピックへ実行要求を通知できること。 |
| BFR-013 | 実行開始通知受付 | Agentからの実行開始通知を受け付け、実行状態を更新できること。 |
| BFR-014 | 実行完了通知受付 | Agentからの実行完了通知を受け付け、実行結果と履歴を保存できること。 |
| BFR-015 | 実行ファイル配布 | Agentが実行に必要なファイル一覧を取得し、ファイルをダウンロードできること。 |
| BFR-016 | タイムアウト管理 | 制限超過時に停止を要求し、停止確認後にtimeoutへ確定すること。結果不明の場合はrunningを維持すること。 |
| BFR-017 | 再通知管理 | MQTT通知に失敗した実行要求を再通知対象として保持できること。 |
| BFR-018 | 重複実行防止 | 同一スケジュール、同一予定時刻の実行要求を重複作成しないこと。 |
| BFR-019 | 無効化・論理削除 | FR-0019に従い新規要求停止・未開始取消・未完了確認と連動すること。取消受付を終了確認とみなさないこと。 |
| BFR-020 | 定義更新競合 | FR-0019に従い更新番号を照合し、古い編集・状態変更による上書きを拒否すること。 |

## 非機能要件

| ID | 要件 | 内容 |
| --- | --- | --- |
| BNFR-001 | 冪等性 | 同一実行要求を複数回通知しても、Agent側で二重実行しない前提の識別子を提供すること。 |
| BNFR-002 | 追跡性 | 実行要求、状態遷移、完了結果、履歴を追跡できること。 |
| BNFR-003 | 可用性 | MQTT通知失敗時も実行要求を失わず、再通知できること。 |
| BNFR-004 | 保守性 | バッチ定義、スケジュール、実行要求、履歴を分離して管理できること。 |
| BNFR-005 | セキュリティ | 管理者向け操作は認証済み利用者に限定すること。 |
| BNFR-006 | 整合性 | 実行状態の正本はDBで管理すること。 |

## 実行状態

| 状態 | 内容 |
| --- | --- |
| queued | 実行要求作成済みで、Agentへ未通知または再通知待ちの状態。 |
| dispatched | AgentへMQTT通知済みの状態。 |
| running | Agentが実行開始済みの状態。 |
| success | 正常終了した状態。 |
| failed | 異常終了した状態。 |
| timeout | タイムアウトによる停止を確認済みの状態。 |
| cancelled | 取消による未開始・停止を確認済みの状態。 |
| expired | 未開始のまま開始期限を超えたことを確認済みの状態。 |

結果不明の場合はrunningを維持し、自動再実行しない。状態遷移は[FR-0020](../FR/0020.md)を参照する。

## 権限要件

管理者はスケジュール一覧で期間内の実行状態別件数を確認し、完了した実行のログを参照できること。
現行の完了ログ対象はsuccess・failed・timeoutに限る。全状態の履歴参照とは区別する。
具体的な検索条件・返却範囲は[スケジュール画面設計](../../06_UserInterfaceDesign/3002_batch_schedule.md)を参照する。

| 操作 | 権限 |
| --- | --- |
| バッチ定義参照 | 管理者 |
| バッチ定義登録・更新 | 管理者 |
| バッチスケジュール参照 | 管理者 |
| バッチスケジュール登録・更新 | 管理者 |
| 手動実行要求作成 | 管理者 |
| 実行結果参照 | 管理者 |


## 追加合意: 定義添付ファイルと共通設定

バッチ定義に実行スクリプト・入力データ・設定ファイルを添付し、実行要求作成時の添付内容で実行する。手動実行画面での追加・差し替えは設けず、定義の編集と再添付で変更する。
Agentは実行IDごとの専用ディレクトリを使用し、必要ファイルの準備失敗時はスクリプトを開始しない。
添付上限と作業ディレクトリ保持期間は管理者がバッチ共通設定画面で変更可能とする。
具体値・変更時の扱いは[ファイル転送詳細設計](../../02_SystemDesign/バッチ管理/Details/0005_batch_file_transfer_detail_design.md)を正本とする。2026年9月23日に定義添付・共通設定・Agent実行へ反映した。
