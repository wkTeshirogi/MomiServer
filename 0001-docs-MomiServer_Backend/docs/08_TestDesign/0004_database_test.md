# DBテスト

## マイグレーション

- 初回起動時にテーブルが作成されること。
- 既存DBに対してマイグレーション管理を開始できること。
- テーブル定義とアプリケーションの参照項目に不整合がないこと。

## 更新日時

対象テーブル更新時に更新日時が変更されることを確認する。

## バックエンドCIの実行前提

2026/10/22時点のバックエンド `.gitlab-ci.yml` では、JDK 25とPostgreSQL 17を使用する。

1. PostgreSQLクライアントを導入し、`pg_isready` でDBの起動完了を待つ。
2. `clean`、`flywayMigrateOnly`、`generateJooq`、`test`、`jacocoTestReport` の順にGradleタスクを実行する。
3. 成否にかかわらずJUnit XML、テストレポート、JaCoCoレポートなどを成果物として保存する。保持期間は1週間とする。

アプリケーション、Flyway、jOOQの接続先はCI用PostgreSQLに統一する。
MQTTとDiscord通知はCI環境変数で無効化する。上記はCI定義の確認結果であり、実行成功を示すものではない。

依存関係検査だけを実行するスケジュールでは単体テストを省略する条件がある。
ジョブごとの実行条件と追加検証は[バックエンドCI検証設計](./0010_backend_ci_test.md)を参照する。
