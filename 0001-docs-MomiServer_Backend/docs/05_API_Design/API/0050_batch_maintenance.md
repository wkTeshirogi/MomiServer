# バッチ保守状態取得・変更

## 基本情報

| 項目 | 内容 |
| --- | --- |
| API ID | API-0050 |
| 分類 | 共通設定・計画更新 |
| メソッド | GET / POST |
| パス | `/api/master/common-settings/batch/maintenance` |
| 認証 | Web JWT必須 |
| 権限 | ADMINのみ。OPERATOR・USER・Agent・外部APIキーは利用不可 |
| 正常ステータス | HTTP 200 |

## 概要

`070_api_design.md`を使用。更新前の新規開始・自動配信を停止し、安全に停止できるか確認する。
自動デプロイ、強制終了、要求の一括取消、バッチ以外の書込停止は実施しない。

## 処理概要

1. ADMIN認可後、GETは保守状態と未確定件数を取得する。
2. POSTは開始・配信の受付境界を排他し、保守状態を永続化する。
3. 受付済みの開始は呼出元トランザクションの終了まで待ち、通常配信はネットワーク送信まで待つ。
4. 実行中バッチの結果受信・取消・期限監視は継続する。
5. 変更後に状態を返す。操作者と変更状態はサーバーログへ記録する。

## リクエストボディ

GETの本文・パスパラメータ・クエリパラメータは不要。POSTは次の値を必須とする。

| 項目 | 型 | 必須 | 制約 | 説明 |
| --- | --- | --- | --- | --- |
| paused | boolean | はい | null・欠損不可 | trueで開始停止、falseで明示再開 |

## レスポンス

| 項目 | 型 | 説明 |
| --- | --- | --- |
| paused | boolean | 保守停止中か |
| unsettled_execution_count | integer | running・dispatched、およびqueuedだが配信試行ありの件数 |
| safe_to_stop | boolean | 保守停止中かつ上記件数0の場合のみtrue |

結果不明は停止済みと断定しない。件数照会失敗時は安全とみなした応答を返さない。
件数はDB上の実行状態であり、全端末・OS・他機能の停止保証ではない。

## 主なエラー

| HTTPステータス | 説明 |
| --- | --- |
| 400 | JSON不正、pausedが欠損・null |
| 401 / 403 | 未認証・管理者以外 |
| 500 | 保守状態の永続化失敗やDB照会失敗。状態を再取得して確認する |

## 備考

- 起動時のマーカー破損・読取り不能は起動エラーとする。未存在のみ通常状態へ初期化する。
- 原子的な同一領域ファイル置換を使用する。対応しないファイルシステムでの保存は失敗扱いにする。
- 複数BE間の共有ロックは提供しない。初期本番の単一BEを前提とする。
- 開始保留応答とAgent更新順は[常駐API](0042_agent_runtime.md)、運用は[停止・再開手順](../../07_OperationsDesign/0004_agent_batch_runtime.md)を参照。
