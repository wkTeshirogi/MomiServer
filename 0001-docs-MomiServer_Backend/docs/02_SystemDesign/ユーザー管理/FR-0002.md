# FR-0002 | ユーザー情報の参照

## 概要

管理者向けにユーザー一覧とユーザー詳細を参照する。

## 対象API

| メソッド | パス | 内容 |
| --- | --- | --- |
| POST | `/api/master/user/list` | ユーザー一覧取得 |
| POST | `/api/master/user/detail` | ユーザー詳細取得 |

## 一覧取得

1. ユーザーをID昇順で取得する。
2. 取得結果を配列として返却する。
3. 対象データが0件の場合は空配列を返却する。
4. パスワードは返却しない。

## 詳細取得

1. ユーザーIDを受け取る。
2. 対象ユーザーを1件取得する。
3. 対象ユーザーが存在しない場合は404を返却する。
4. パスワードは返却しない。

## レスポンス項目

| 項目 | 型 | 説明 |
| --- | --- | --- |
| id | number | ユーザーID |
| email | string | メールアドレス |
| role | string | 権限 |
| createdDt | string | 作成日時 |
| updatedDt | string | 更新日時 |
| lastLoginAt | string | 最終ログイン日時 |

## 権限

管理者権限を持つユーザーのみ利用できる。

## 本人向け個人設定の構成

前述の管理者向け参照APIとは別に、`/settings`と`/api/users/me/settings`配下を提供する。
通常のWebロールが本人の表示名・パスワード・テーマだけを変更できる。
対象メールアドレスはAuthenticationから取得し、利用者が送った対象ID・メール・権限を更新条件にしない。

| 構成要素 | 責務 |
| --- | --- |
| 個人設定画面 | 入力・確認・保存通知。パスワードはブラウザ内の入力状態以外へ保存しない |
| 個人設定Context | ログイン単位の設定取得とテーマ同期。古いログインの遅い応答を破棄 |
| 個人設定Controller・Service | 本人を特定し、項目ごとの更新とパスワード照合を実施 |
| UserRepository | 専用更新によりロール・メール・他の個人設定を変更しない |
| AuthSessionService | パスワード変更時に本人の全セッションを失効 |

パスワード変更はユーザー行をロックし、ハッシュ更新と全セッション失効を同一トランザクションで実行する。
ログインも同じ行をロックして、旧パスワードで認証したセッションが変更後に残る競合を防ぐ。
既存のJWT照合処理により、失効後のアクセス・更新トークンを拒否する。
ユーザー名変更とテーマ変更ではセッションを失効しない。

テーマはDB値を正とし、ブラウザ保存値は初期描画用のキャッシュとして扱う。
設定画面と右上ボタンを同期し、保存失敗時は変更前のテーマへ戻して上部へエラー表示する。
入力契約は[個人設定API](../../05_API_Design/API/0049_personal_settings.md)、表示は[画面設計](../../06_UserInterfaceDesign/3010_personal_settings.md)を参照する。
