# 外部APIキー・在庫連携設計

## 概要

外部連携先ごとに発行するAPIキーで在庫の参照・数量操作を許可する。
2026/10/20の合意と2026/10/24の運用仕様確定を反映する。
`040_basic_design.md`および`050_detail_design.md`テンプレートの構成を基に整理した。

## 目的

WebユーザーやAgentの認証情報を外部システムへ渡さず、必要な在庫操作だけを公開する。

## 対象範囲

| 区分 | 内容 |
| --- | --- |
| 対象 | 在庫一覧・詳細、既存在庫への入庫・出庫・棚卸し、ADMINによるキー発行・一覧・無効化 |
| 対象外 | 品目マスター編集、在庫新規登録・無効化、Web・Agent APIへのキー認証流用 |
| 将来拡張 | 車庫管理はPhase 1対象外。専用スコープと観測APIは将来設計・追加し、既存キーへ自動付与しない |

## 全体構成

管理画面はユーザーJWTとADMIN権限で操作する。外部APIは専用パスの認証フィルターでキーを検証する。
有効なキーには外部連携専用権限と指定スコープのみを設定し、発行したADMINの権限は継承しない。

## 構成要素

| 構成要素 | 役割 |
| --- | --- |
| `/master/api` | 発行・API一覧はモーダル。発行通知はモーダル内、無効化・取得・コピー結果はページヘッダー直下 |
| 外部APIキー管理 | 秘密値生成、ハッシュ保存、発行・無効化監査 |
| 外部API認証 | 要求ごとの失効確認、スコープ付与、DB共有レート制限 |
| 外部在庫連携 | 公開項目の限定、入力検証、重複防止、既存在庫操作への接続 |

## 管理項目

| 項目 | 内容 | 必須 |
| --- | --- | --- |
| 連携先名 | 1～100文字。用途・環境を識別する名称 | はい |
| スコープ | `inventory:read`、`inventory:write`。参照は更新に暗黙付与しない | 1件以上 |
| 有効期限 | 未来日時。画面初期値は発行から1年。無期限はADMINが明示的に選択する | 無期限選択時は不要 |
| 識別子 | UUIDと秘密値の先頭12文字。秘密値全体の再表示には使用できない | 自動 |
| 監査情報 | 発行者・発行日時、最終利用日時、無効化者・日時 | 自動 |

## 主要処理

### 発行単位・スコープ

連携システム・用途・環境ごとに別キーを発行し、使い回さない。
連携先名で用途と環境を識別する。Phase 1で新たな管理項目やスコープは追加しない。

| スコープ | 許可する操作 |
| --- | --- |
| `inventory:read` | 公開対象在庫の一覧・詳細参照 |
| `inventory:write` | 公開対象の既存在庫への入庫・出庫・棚卸 |

`inventory:write`に参照権限は暗黙付与しない。ただし、数量操作の応答には操作後の在庫情報を含める。
品目・保管場所ごとのアクセス制限はPhase 1で追加せず、既存の公開対象条件を維持する。
車庫管理向けの未使用スコープを先行追加せず、将来のAPI設計確定後に追加する。

### 発行・無効化

暗号学的乱数32バイトをURL安全な形式に変換し、接頭辞`momi_`を付ける。
SHA-256ハッシュと識別用の先頭部分だけをDBへ保存する。原文は発行応答と画面の一時状態だけで保持する。
発行応答は`Cache-Control: no-store`とし、画面のダイアログを閉じると原文を破棄する。
ブラウザ保存領域には原文を保存しない。コピーは利用者が明示操作した場合だけ行う。

発行・無効化と監査履歴はそれぞれ同一トランザクションで保存する。
監査履歴には操作者・日時・対象キーを記録し、キー原文を含めない。
無効化は繰り返しても成功し、初回だけ監査記録を作成する。
無効化前の確認画面にはキー名・識別用プレフィックス・最終利用日時を表示する。
交換・スコープ変更は新キー発行、連携先切替、旧キー無効化の順で行い、切替中は新旧キーの併用を許可する。
専用の再有効化・ローテーションAPIは提供しない。

有効期限の画面初期値は発行から1年とし、期限を指定しない場合はADMINによる無期限の明示選択を必要とする。
画面表示時と発行成功後のフォーム初期化時に、ローカル日時の1年後を設定する。
2月29日の翌年が平年なら2月末日へ補正する。利用者が変更した期限は、発行時にUTCの日時へ変換して送信する。
既存の無期限キーの期限を自動変更しない。管理APIの未指定・NULLを無期限とする既存契約は維持する。
今回の追加は画面操作の安全性向上であり、APIに新たな無期限フラグを追加するものではない。

### 認証・レート制限

本番通信はHTTPS、キー送信は`X-API-Key`ヘッダーに限定する。URLや本文へキーを含めない。
`/api/v1/external/**`ではWeb JWTやAgent Bearerを代用できない。
IoT向けGateway認証の無効化設定にかかわらず、外部キーの検証は必須とする。
バージョン公開状態は`m_api_versions`の`external/v1`で判定する。

無効化・期限切れは要求ごとのDB確認で拒否する。認証情報はキャッシュしない。
無効化が確定する前に認証済みとなった処理の取消までは行わない。
キーごとに毎正時リセットの1時間固定ウィンドウで1000回まで許可し、DBの原子更新で複数プロセス間も共有する。
認証成功後はスコープ不足や入力不正、同一操作の再送も回数へ計上する。
上限・残回数・リセット時刻を応答ヘッダーへ設定し、超過時は`Retry-After`も返す。

### 在庫数量操作・重複防止

有効な品目に属し、削除状態ではない実在庫だけを公開・更新する。
公開情報は品目名、メーカー、型番、カテゴリ、保管場所、数量、最低数量、単位、在庫状態と識別IDに限定する。
内部メモ・購入先などは公開しない。数量操作は既存の行ロック・履歴保存・在庫状態判定・通知処理を使用する。

キーIDと操作IDの組み合わせを一意にし、在庫更新・履歴・初回応答保存と同一トランザクションで確保する。
同一操作ID・同一入力の再送は初回応答を返す。途中で別操作があっても現在値ではなく初回応答を返す。
対象在庫、操作種別、数量、理由が異なる再送は409とし、在庫を更新しない。
同時再送はDB一意制約で待ち合わせる。失敗時は操作記録もロールバックし、同じ入力で再試行できる。

## 状態遷移

| 状態 | 説明 | 次の状態 |
| --- | --- | --- |
| `ACTIVE` | 有効期限内または無期限なら利用可能 | `REVOKED` |
| `REVOKED` | 永続的に利用不可 | なし |
| 期限切れ | 有効期限から導出する表示状態。DB状態は変更しない | ADMINによる無効化のみ |

## 入力チェック

| チェック | 内容 |
| --- | --- |
| 数量 | 0以上の整数。入庫による整数上限超過、出庫による負数は拒否 |
| 操作 | `inbound`、`outbound`、`stocktake`のみ |
| 操作ID | UUID必須。キー交換後は別の重複防止範囲となるため、未確定操作を新キーで再送しない |
| 一覧 | 既定20件。`limit`は1～100、`offset`は0以上 |

## データ方針

| データ | 方針 |
| --- | --- |
| 秘密値 | 発行時のみ表示、DBとログへ原文を残さない |
| キー・監査・操作記録 | 自動物理削除は行わない。重複防止の保持期間短縮は別途設計する |
| APIアクセスログ | `source_type=gateway`、認証済み主体は`external:<キーUUID>`。ヘッダー・本文は記録しない |

## エラー方針

| 事象 | 対応 |
| --- | --- |
| キー未指定・不正・期限切れ・無効化済み | 401 |
| スコープ不足・管理権限不足 | 403 |
| 対象在庫なし・非公開在庫 | 404 |
| 同じ操作IDで異なる入力 | 409 |
| 入力不正・在庫不足・数量上限超過 | 400 |
| 時間あたり上限超過 | 429 |
| キー検証のDB参照不可 | 503。認証を省略しない |

## 2026/10/24確定仕様の反映状況

仕様確定後、有効期限入力と無効化確認をフロントエンドへ実装した。
続けて発行フォームをモーダル化し、全体・キー別の利用可能API一覧モーダルを追加した。
DB・バックエンドAPI・既存キーの値は変更していない。

| 区分 | 状況 |
| --- | --- |
| 既存機能を維持 | ADMIN限定、2スコープ、数量操作3種、監査、要求ごとの失効判定、新旧キーの併用 |
| 運用ルール | 連携システム・用途・環境単位の発行、連携先切替後の旧キー無効化 |
| 画面の実装 | 有効期限の初期値1年、無期限の明示選択、無効化確認への識別情報追加を実装 |
| 試験 | 追加画面仕様の回帰試験を実施。今回の試験と既存バックエンド試験の区別はテスト設計を参照 |
| Phase 1対象外 | 車庫管理API・専用スコープの追加。既存キーへ将来権限を自動付与しない |
