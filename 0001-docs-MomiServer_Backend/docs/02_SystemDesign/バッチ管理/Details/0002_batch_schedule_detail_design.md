# バッチスケジュール管理 詳細設計

## 目的

バッチ定義に対し、対象Agent、Cron式、実行期間、休日実行可否、優先度を設定して実行スケジュールを管理する。

## 対象操作

| 操作 | 内容 |
| --- | --- |
| 一覧参照 | 登録済みのバッチスケジュールを一覧で参照する。 |
| 詳細参照 | バッチスケジュールIDを指定して詳細を参照する。 |
| 登録 | 新しいバッチスケジュールを登録する。 |
| 更新 | 既存のバッチスケジュールを更新する。 |

## 管理項目

| 項目 | 内容 | 必須 |
| --- | --- | --- |
| batch_definition_id | 紐づくバッチ定義ID。 | 必須 |
| target_agent_id | 実行対象Agent ID。 | 必須 |
| cron_expression | 実行スケジュールを表すCron式。 | 必須 |
| start_date | 実行開始日。 | 任意 |
| end_date | 実行終了日。 | 任意 |
| allow_holiday_execution | 休日実行可否。 | 必須 |
| enabled | 有効状態。 | 必須 |
| priority | 優先度。 | 必須 |

## 登録・更新判定

| 条件 | 処理 |
| --- | --- |
| ID未指定 | 新規登録する。 |
| IDが0以下 | 新規登録する。 |
| ID指定あり | 既存スケジュールを更新する。 |
| ID指定ありで対象なし | エラーとする。 |

## 入力チェック

| チェック | 内容 |
| --- | --- |
| バッチ定義存在 | 指定したバッチ定義が存在すること。 |
| 対象Agent存在 | 指定した対象Agentが存在すること。 |
| Cron式 | Cron式として解釈できること。 |
| 実行期間 | 開始日と終了日の前後関係が正しいこと。 |
| 優先度 | 許可された範囲の優先度であること。 |

## 実行判定

| 条件 | 内容 |
| --- | --- |
| スケジュール有効 | 有効状態であること。 |
| バッチ定義有効 | 紐づくバッチ定義が有効であること。 |
| 実行期間内 | 現在日時が開始日以降かつ終了日以前であること。 |
| Cron一致 | 現在時刻がCron式に一致すること。 |
| 重複なし | 同一予定時刻の実行要求が存在しないこと。 |

## 出力

登録・更新後は、保存後のバッチスケジュール詳細を返却する。

## 実行予定・履歴参照の追加方針

### 2026/10/02時点の実装範囲

BatchScheduleMasterController、BatchScheduleService、BatchScheduleExecutionRepositoryで以下を実装する。

| 機能 | 処理 |
| --- | --- |
| 状況集計 | schedule_idがある要求を予定日時で抽出し、スケジュール・日付・時間帯・状態別に件数集計 |
| 完了ログ | スケジュール・予定日・任意の時間帯を指定し、success・failed・timeoutのみ取得 |
| ページング | 51件を検索し、先頭50件と残件有無を返す。予定日時降順、同日時では内部ID降順 |
| 権限 | Controller全体にAdminOnlyを適用 |

DBの予定日時を日付・時間へ分解する。応答日時はタイムゾーンのオフセットを含まない。
API契約は[状況集計](../../../05_API_Design/API/0043_batch_schedule_executions.md)と
[完了ログ](../../../05_API_Design/API/0044_batch_schedule_execution_logs.md)を参照する。

### 全履歴表示の追加方針（現行実装とは区別）

2026年9月17日決定。スケジュール詳細から実行回ごとの予定・履歴を参照できるようにする。
状態ごとの表示項目、スナップショットの参照時点、機密情報の扱いは
[バッチスケジュール画面設計](../../../06_UserInterfaceDesign/3002_batch_schedule.md) を正とする。

- 実行要求は `schedule_id` で絞り込み、`execution_id` を用いて各回の結果・ファイル情報と関連付ける。最新結果だけでスケジュール全体の状態を表さない。
- 実行要求生成前の予定値は現在の定義から算出したプレビューとして返す。画面参照によって実行要求を作成しない。
- 生成済み要求は保存されたスナップショットを返す。実行結果・配布状態はその要求に関連する記録から取得し、現在の親データから過去の値を再構築しない。
- 実行状態と確認状態を区別して返し、結果未確認や未取得の日時・終了コードを成功値で補完しない。
- 参照権限を確認したうえで、機密値を除いた表示用データを返す。Agent向けの実行要求をそのまま画面用レスポンスに流用しない。

本追記は設計方針の記録であり、既存APIがこれらの項目を返却できることを保証しない。
追加・拡張するAPIとDB保存項目は、画面設計の未確定事項に沿って別途具体化する。
