# バッチ定義マスタ管理

## 概要

バッチ処理の実行方法、実行条件、ログ、通知、実行に必要な配布ファイルに関する定義情報を管理する。

Phase 1の「タスク管理」はこのバッチ管理を指し、人向けの汎用ToDo管理は含めない。
2026/10/09の確定要件と完了条件は[FR-0019](../../01_RequirementsDefinition/FR/0019.md)を正本とする。

## 対象API

| No | API | 概要 |
| --- | --- | --- |
| 1 | `/api/master/batch/list` | バッチ定義一覧取得 |
| 2 | `/api/master/batch/detail` | バッチ定義詳細取得 |
| 3 | `/api/master/batch/register` | バッチ定義登録・更新 |

## 登録・更新

- IDが未指定または0以下の場合は新規登録する。
- IDが指定されている場合は既存レコードを更新する。
- 更新対象が存在しない場合はエラーとする。
- バッチ名、表示名、カテゴリ、実行種別、実行コマンド、ログパスは必須とする。
- 実行に必要なスクリプト、入力ファイル、設定ファイルは定義画面で管理する。定義保存と添付の確定は別操作とする。
- 配布ファイル専用の画面は設けない。

## 更新・無効化・削除の確定仕様

以下は合意済みの設計要件であり、実装完了を示すものではない。

| 操作 | 設計 |
| --- | --- |
| 定義更新 | 作成済み要求を変更せず、新しく作成する要求へ反映 |
| 無効化 | 新規要求作成を停止し、作成済み未開始要求を取消対象にする。実行中は別途取消操作 |
| 論理削除 | 無効化済みで未完了要求がないことを確認し、削除状態へ更新。履歴・参照中の添付は保持 |
| 更新競合 | 定義の`version`照合と原子的加算。編集・有効／無効切替・論理削除で共通使用し、競合は409 |
| 競合時の画面 | 上部エラーと入力保持。自動再保存せず、再取得は利用者が選択 |

無効化と新規要求作成、取消とAgent開始、削除と未完了要求の追加が競合しても、
上記条件を破らない整合性制御が必要となる。具体的なDB・API契約とテストの追加は残対応とする。
取消の受付だけで終了済みとは判定しない。

## 主な項目

| 項目 | 内容 |
| --- | --- |
| batch_name | バッチの内部識別名 |
| view_name | 画面表示名 |
| category | 分類 |
| execution_type | 実行種別 |
| execution_command | 実行コマンド |
| working_directory | 作業ディレクトリ |
| timeout_seconds | タイムアウト秒数 |
| max_retry_count | 最大リトライ回数 |
| retry_interval_seconds | リトライ間隔秒数 |
| allow_parallel_execution | 並列実行可否 |
| log_retention_date | ログ保持期限 |
| log_path | ログ出力先 |
| success_notification | 成功時通知 |
| failure_notification | 失敗時通知 |

## 配布ファイル管理

| 項目 | 内容 |
| --- | --- |
| 管理単位 | バッチ定義単位 |
| 登録方法 | 定義を先に保存し、同画面の添付確定操作で即時登録する |
| 対象ファイル | 入力ファイル、実行スクリプト、設定ファイル、Agent更新ファイル |
| 保存先 | ファイル本体はストレージ、メタ情報は `m_batch_files` |
| 実行時の固定 | 要求作成時に添付参照・配置先・サイズ・SHA-256を固定する。具体的な現行契約は下記の詳細設計を参照 |

配布ファイルはバッチ定義マスタの一部として扱う。
画面上もバッチ定義登録・更新画面内でファイルを追加、差し替え、解除できる方針とする。
現行の保存・配布方式は[ファイル転送詳細設計](Details/0005_batch_file_transfer_detail_design.md)の
「添付実装で具体化した事項」を参照する。旧転送UUID方式との混同を避ける。
