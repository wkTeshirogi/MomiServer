# 共通トークンハッシュ基本設計

## 概要

認証セッション、Agent、外部連携で重複する文字列ハッシュと定時間比較をTokenHashesへ集約する。

## 目的

保存済みハッシュとの互換性と比較方法を保ち、認証方式ごとの実装のずれを防ぐ。

## 対象範囲

| 区分 | 内容 |
| --- | --- |
| 対象 | リフレッシュトークン、Agentのトークン・コード等、外部APIキーと既存の重複防止用文字列ハッシュ |
| 対象外 | パスワード、JWT署名、AES暗号化、ファイルのストリームチェックサム、認可方式の変更 |

## 全体構成

各認証・連携処理から共通処理へ元の文字列を渡し、従来と同じハッシュを既存Repositoryで保存・照会する。
AgentSecrets・ExternalSecretsの既存窓口は共通処理へ委譲し、呼出元の契約を維持する。

## 構成要素

| 構成要素 | 役割 |
| --- | --- |
| TokenHashes.sha256 | UTF-8文字列からSHA-256の小文字16進64文字を生成 |
| TokenHashes.matches | 計算済み固定長ハッシュを先頭にMessageDigest.isEqualで比較 |
| common.constants.TokenHashConstants | 共通カテゴリのconstants配下でアルゴリズム名を定義。TokenHashesから参照 |
| 各認証・連携Service | 乱数生成、期限、署名、暗号化、元文字列の組立てと認可を維持 |

## 主要処理

| 処理 | 方針 |
| --- | --- |
| 生成 | 空白・大文字小文字・Unicodeを正規化せず、入力のUTF-8バイト列をそのまま使用 |
| スレッド安全性 | MessageDigestを呼出しごとに生成し、可変状態を共有しない |
| 比較 | nullは不一致。不正な保存値の補正や大小文字変換を行わない |
| 互換性 | 既存AuthSessionの16進変換、Agent・外部連携のHexFormatと同じ結果 |

## データ方針

- 保存値・照合用SQL・元文字列の構造・トークン原文の非保存方針は変更しない。
- DBマイグレーション、既存データの再生成、トークンの再発行・強制失効は不要。
- パスワードのBCryptをSHA-256へ置き換えない。

## エラー方針

SHA-256を使用できない場合はIllegalStateExceptionとし、安全性を弱める代替方式へ切り替えない。
null入力は従来と同様に拒否し、空文字列への暗黙変換を行わない。
