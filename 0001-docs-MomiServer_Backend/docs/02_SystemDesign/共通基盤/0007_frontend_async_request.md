# FE共通非同期取得 基本設計

## 概要

通常のHTTP取得に共通フックを導入し、初期取得・再取得・古い応答の抑止・アンマウント時の処理を集約する。

## 目的

古い成功・失敗・終了処理が新しい画面状態を上書きすることを防ぎ、取得動作の保守性を高める。

## 対象範囲

| 区分 | 内容 |
| --- | --- |
| 対象 | 通常のマスタ・在庫・車両一覧、状態画面のHTTP取得、ログ検索と詳細、APIキー一覧、ID付きフォームの通常取得 |
| 固有制御を維持 | 認証更新、通知ポーリングと既読の連動、WebSocket、原本プレビュー、複数段の業務手順を持つ取得 |
| 対象外 | API契約、更新処理の自動中止、データキャッシュ基盤や新規ライブラリの導入 |

## 全体構成

各画面からuseAsyncResourceまたはuseAsyncRequestを使用し、createAsyncRequestScopeが取得レーンの所有権を管理する。
HTTPクライアントへAbortSignalを渡せる場合は通信を中止し、非対応の場合も結果の反映を抑止する。

## 構成要素

| 構成要素 | 役割 |
| --- | --- |
| createAsyncRequestScope | 最新取得の成功・失敗・終了処理だけを実行する、Reactに依存しない処理 |
| useAsyncRequest | コンポーネントに取得レーンを結び付け、アンマウント時に無効化 |
| useAsyncResource | data・loading・error・reloadと、条件変更時の開始予約・中止を共用 |
| 各画面 | ID検証、通知文言、フォーム更新、別リソースの組合せ、更新処理を保持 |

## 主要処理

| 処理 | 方針 |
| --- | --- |
| 新しい取得 | 同じレーンの以前のAbortControllerを中止し、新しい所有権へ切り替える |
| 古い結果 | クライアントがAbortSignalを無視しても成功・失敗・終了処理を反映しない |
| 画面変更 | 条件変更・アンマウントで予約と進行中取得を無効化 |
| 複数リソース | サービスと端末、スケジュールと実行状態等は別レーンとし、互いを中止しない |
| APIキー更新 | 発行・無効化前に古い一覧取得を無効化し、更新後の一覧を上書きさせない |
| フォーム | マスタ未検出や不正IDの業務文言は各画面で維持 |

## 状態遷移

| 状態 | 説明 | 次の状態 |
| --- | --- | --- |
| 取得中 | 最新レーンだけが結果を反映できる | 成功・失敗・無効化 |
| 成功 | 最新のデータを反映して読み込み終了 | 再取得 |
| 失敗 | 指定の文言と保持・クリア方針を反映 | 再取得 |
| 無効化 | 古い成功・エラー・終了通知を破棄 | 新しい取得、またはアンマウント |

## データ方針

- APIログ・実行ログは取得開始時に行、次ページ有無、総件数をクリアする。
- 通常一覧の既存データ保持、実行状態の取得失敗時クリア等は用途別の指定を維持する。
- APIエラー本文を使うか固定文言にするかは画面が指定し、既存の通知位置・入力保持は変更しない。
- load関数の参照はモジュール関数かuseCallbackで安定させ、再描画ごとの再取得を防ぐ。

## エラー方針

古い取得の失敗と中止は通知しない。最新取得の失敗だけを画面へ渡す。
保存・入出庫等の更新処理を、HTTP取得レーンのキャンセルへ混在させない。
