# 個人設定画面設計書

## 概要

`080_ui_design.md`テンプレートを使用した。
ADMIN・OPERATOR・USERが、右上のユーザーメニュー「設定」から`/settings`を開き、本人の設定だけを変更する。
通知設定、メールアドレス変更、管理者向けロール変更は設けない。

## 画面構成

ページ上部に結果通知を置き、ユーザー名、パスワード変更、表示設定を独立したセクションとして縦に並べる。
パスワードとユーザー名は独立したフォームとし、一方の保存で他方を送信しない。

## コンポーネント詳細

| 要素 | 仕様 |
| --- | --- |
| ユーザー名 | 登録済み表示名を入力。未設定は空欄。保存後は右上メニューにも反映 |
| パスワード変更 | 現在・新規・確認用をマスク入力。変更成功時に入力と認証情報を消去しログインへ遷移 |
| 再ログイン案内 | ログイン画面上部に変更成功のNotificationBannerを表示 |
| 表示設定 | ライト・ダークのラジオ選択。変更を即時反映し自動保存 |
| 右上テーマボタン | 設定画面と同じ保存処理を使用し、設定内容を同期 |

## 入力項目

入力項目と制約は[個人設定API](../05_API_Design/API/0049_personal_settings.md)を参照する。
パスワードをURL・ブラウザストレージ・再ログイン用の画面状態へ保存しない。

## 状態管理

| 状態 | 表示・操作 |
| --- | --- |
| 取得中 | 読み込み中を表示し、未取得の値で編集させない |
| 取得失敗 | 上部にエラーと再取得ボタン。設定フォームを表示しない |
| 保存中 | 関連入力・保存・テーマ切替を非活性化し、二重送信を抑止 |
| テーマ保存失敗 | 保存済みのテーマへ戻し、上部にエラー表示 |
| パスワード変更失敗 | 入力を保持し、ログイン状態を維持。認証期限切れは既存処理で再ログイン |

## 操作フロー

1. ログイン時または認証復元時に個人設定を取得し、DBのテーマを適用する。
2. 設定画面で表示名の保存、パスワード変更、テーマ選択を個別に行う。
3. 成功・失敗はページ上部に表示する。テーマ変更で未保存の表示名を消さない。
4. パスワード変更成功後はサーバー側失効済みのため、追加のログアウト・トークン更新APIを呼ばず再ログインする。

古いログインの遅い取得・保存応答を現在の設定へ反映しない。
テーマのブラウザ保存値は初期表示用とし、DB値の取得成功後に置き換える。

## エラーハンドリング

入力不足、短すぎるパスワード、確認不一致、通信失敗は上部のNotificationBannerへ表示する。
保存成功と他項目の失敗を混同せず、パスワード変更失敗時にログアウト成功と表示しない。

## アクセシビリティ

入力へラベルと自動補完属性を設定する。テーマはfieldset・legendとラジオでまとめる。
通知は成功をstatus、失敗をalertで伝える。右上のアイコン操作に説明用の名前を付ける。

## レスポンシブ対応

PCでは入力幅を制限して縦配置し、スマートフォンでは画面幅に収める。
長いユーザー名やエラー文は折り返し、ダーク・ライト双方で読める配色とする。

## 実装ファイル

| 種別 | パス |
| --- | --- |
| 画面 | `src/pages/Settings` |
| 個人設定の取得・保存 | `src/contexts/PersonalSettingsContext.tsx`、`src/api/personalSettingsApi.ts` |
| 既存認証・テーマとの接続 | AuthContext、ThemeContext、Header、Layout、LoginPage |
