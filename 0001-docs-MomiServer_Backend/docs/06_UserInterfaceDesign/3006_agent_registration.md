# エージェント登録管理 画面設計書

## 概要

2026年9月14日、登録CLIの合意を管理画面・バックエンド連携へ反映する。
管理者が基本情報を登録し、登録コードを発行してWindows・Linux・macOSの端末登録を案内する画面とする。
端末にGUIやブラウザーを要求しない。LinuxではSSHまたはコンソールから登録できる。
2026年9月23日、端末マスタ詳細 `/master/machine/{id}` にコード発行・状態取得・無効化・再登録開始を実装した。MQTT接続状態の実監視は未実装。

コードの期限・利用回数・再発行・端末交換条件は
[エージェント登録詳細設計](../02_SystemDesign/認証/0004_agent_registration.md)を正とする。
実装した契約は[Agent登録・専用認証API](../05_API_Design/API/0041_agent_registration_authentication.md)を参照する。

## 画面構成

基本情報、登録コードと端末操作案内、登録・接続状況の3領域を設ける。
端末マスタ詳細の基本情報の下にAgent登録領域を配置する。保存前の新規端末には表示しない。

## コンポーネント詳細

| 領域 | 表示・操作 |
| --- | --- |
| 基本情報 | エージェント名・対象マシン等の入力、保存、エージェントIDの表示。 |
| コード発行 | 保存済みの対象に対して発行・再発行を要求し、コードと有効期限を表示する。 |
| 端末操作案内 | 登録CLI、バックエンド接続先、非表示の対話入力を案内する。 |
| 状況表示 | 端末未登録／バックエンドで登録受理済みと、接続状態・最終受信時刻を分けて表示する。 |
| 端末交換 | 管理者が明示的に再登録を開始する。旧認証情報が失効する影響を表示する。 |

成功・失敗・入力不備のメッセージは、既存方針に従い画面上部のヘッダー直下に表示する。
コードの生成・照合・状態遷移はバックエンドが行い、画面内の判定だけで登録済みとはしない。

## 入力項目

| 項目 | 入力元 | 制約・用途 |
| --- | --- | --- |
| エージェント名 | 管理者 | 表示上の識別名。長さ・必須条件はマスタ設計で確定する。 |
| 対象マシン | 管理者 | 既存マシン情報と紐付ける。対象の選択条件は別途確定する。 |
| バックエンドURL | 管理対象端末から到達可能な接続先設定 | ブラウザーのURLから機械的に推測しない。HTTPSの接続先を案内する。 |
| 登録コード | バックエンドの発行結果 | 端末のCLIへ入力する。画面で任意生成しない。 |

## 状態管理

| 状態 | 表示・動作 |
| --- | --- |
| 基本情報未保存 | 保存完了前にコードを発行しない。 |
| 端末未登録 | コード発行と端末操作を案内する。 |
| コード発行要求中 | ボタンの重複操作を防ぎ、応答後に表示を更新する。 |
| 有効なコードあり | コード、有効期限、登録手順を表示する。 |
| 期限切れ・無効化 | 使用を案内せず、必要に応じて再発行を案内する。 |
| バックエンドで登録受理済み | 登録済みとして表示するが、端末の保存完了やMQTT接続成功までは断定しない。 |
| 登録済み・未接続／切断 | 再登録を促す前に常駐サービス・通信設定の確認を案内する。 |

初期案では状態の再取得操作を設け、自動更新方式・周期は別途確定する。
端末のローカル保存完了はバックエンドで直接確認できないため、画面に推測で表示しない。

## 操作フロー

1. 管理画面で基本情報を保存する。
2. 登録コード発行を操作し、バックエンドが返すコードと有効期限を確認する。
3. 対象端末で下記のCLIを実行する。SSH接続先で実行してもよい。
4. CLIが認証情報を保存した結果を確認する。
5. 管理画面で登録受理・接続状況を再取得して確認する。

### 画面で案内する端末コマンド

| 用途 | コマンド形式 |
| --- | --- |
| 設定済みの接続先へ登録 | `momiserver-agent register <登録コード>` |
| 接続先を明示 | `momiserver-agent register <登録コード> --server https://example.com` |
| コードを非表示で対話入力 | `momiserver-agent register` |

バックエンドURLは端末の設定ファイルから取得し、明示オプションを優先する。
コード引数はシェル履歴・プロセス一覧に残り得るため、対話入力も選べることを案内する。
コードを含むコマンドや専用認証情報を通常ログ・画面分析ログへ記録しない。
画面には専用認証情報そのものを表示しない。

CLIの保存・再試行・引継ぎの詳細は、エージェント設計リポジトリの
`docs/02_SystemDesign/Details/010_agent_registration.md`を参照する。
登録後の常駐サービス登録・起動手順は別途定義し、このコマンドだけで自動起動すると案内しない。

## エラーハンドリング

| 条件 | 表示・挙動 |
| --- | --- |
| 入力不備・権限不足 | バックエンドの判定に従って画面上部へ表示し、保存済み状態を誤更新しない。 |
| コード発行の応答消失 | 発行済みかを確認する。無条件の再発行で既存コードを置き換えない。確認APIは別途設計する。 |
| コード期限切れ | 管理画面で再発行し、新しいコードを端末へ入力するよう案内する。 |
| 端末登録の応答消失 | 同じ端末・同じ登録要求での再試行を案内する。基本情報を重複登録しない。 |
| 登録受理済みだが端末保存失敗 | CLIで保存先・権限と登録復旧を確認する。画面では保存完了と断定しない。 |
| MQTTだけ接続失敗 | 登録と接続の問題を分け、通信・接続設定の確認を案内する。 |

## アクセシビリティ

入力・発行操作をキーボードで操作できるようにし、結果と期限切れは色だけで伝えない。

## レスポンシブ対応

狭い画面でも領域を縦に配置し、コード・URL・コマンドの確認を妨げない。

## 実装ファイル

フロントエンドの配置先・画面URL・管理者権限の具体名は未確定。
本書追加ではフロントエンドやバックエンドのプログラムを変更しない。

## 今後の拡張ポイント

自動状態更新、コードのコピー操作、登録後の運用画面への遷移は既存UIとの整合を確認して具体化する。

## 実装時の表示・操作

- 登録コードは画面メモリだけに保持し、期限・画面離脱・状態再取得で消去する。再表示APIは設けない。
- 状態取得APIで未使用コードの期限は確認できる。発行応答が失われた場合は明示的に再発行する。
- 無効化・再登録では理由入力と影響の確認を必須にする。
- 最終認証確認はme APIの受信日時であり、Online判定ではない。MQTTは「未構成」と表示する。
