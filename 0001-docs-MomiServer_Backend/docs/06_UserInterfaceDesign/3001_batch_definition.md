# バッチ定義画面設計書

## 概要

バッチ定義マスタの一覧表示、詳細確認、登録・更新、論理削除を行う画面。
バッチ名、表示名、実行コマンド、実行制御、ログ、通知設定を管理する。

## 対象ルート

| 画面 | パス | コンポーネント |
| --- | --- | --- |
| 一覧 | `/master/batch/difinition` | `BatchDefinitionList` |
| 詳細 | `/master/batch/difinition/:batchDefinitionId` | `BatchDefinitionDetail` |
| 互換ルート | `/Master/Batch/Difinition/List` | `BatchDefinitionList` |
| 互換ルート | `/Master/Batch/Difinition/Detail/:batchDefinitionId` | `BatchDefinitionDetail` |

## 状態管理

| 状態 | 説明 |
| --- | --- |
| loading | API 取得中 |
| error | 取得または保存エラー |
| saving | 保存中 |
| saved | 保存成功 |
| fieldErrors | 入力項目単位の検証エラー |
| conflicted | 更新番号が競合し、入力を保持して最新データの再読込を待つ状態 |

## 更新競合・論理削除

- 詳細取得時の`version`を保存時に送信する。
- HTTP 409の場合は入力内容を保持し、ページ上部にエラーと「最新を再読込」操作を表示する。
- 最新データは利用者が明示的に再読込し、自動的な上書き再送信は行わない。
- 削除操作は定義を無効化して保存した後だけ利用可能とする。
- 削除成功後は一覧へ戻り、ページ上部に成功通知を表示する。
- 削除済み定義は通常一覧へ表示せず、Phase 1では復元操作を提供しない。

## 注意事項

- 実装上、URL とディレクトリ名に `difinition` / `Difinition` の表記が残っている。
- 既存 URL 互換性を維持する場合は、表記修正時に redirect または互換 route を残す必要がある。


## 追加設計: 実行用ファイルとバッチ共通設定

本節は添付画面と共通設定に実装済みの仕様。制約と設定値の正本は[ファイル転送詳細設計](../02_SystemDesign/バッチ管理/Details/0005_batch_file_transfer_detail_design.md)とする。

バッチ定義の編集に実行用ファイルの添付・再添付・解除を設ける。添付対象にはスクリプト自体を含める。配置先は実行専用ディレクトリからの相対パスとし、同一定義内の重複は大文字・小文字を区別せずエラーとする。
手動実行画面にファイル追加・差し替えは設けない。変更が必要な場合は定義編集へ戻る。実行コマンドにはインタープリターと相対パスを指定し、添付実行の開始位置は実行IDごとの専用ディレクトリとなることを案内する。

バッチ共通設定画面に、1ファイル最大サイズ・定義内合計サイズ・最大添付数・作業ディレクトリ保持期間の編集項目を追加する。サイズはMiB、保持期間は日で入力する。
上限引き下げで超過した定義は警告表示し、新規添付と新しい実行要求の作成を制限する。既存ファイルを勝手に消さず、添付解除によって解消できるようにする。
保持期間の変更は新しい実行要求から適用され、未送信結果の保持とは別設定であることを表示する。


添付欄は定義保存後に使用する。ファイル選択・ドロップで候補を追加し、配置先と種別を編集して「添付を確定」する。確定は定義保存と独立した即時操作で、画面上に明記する。
一覧に元名・配置先・サイズ・登録日時を表示する。差し替えは新規添付として登録し、解除後も既存実行要求は変更しない。処理結果はページ上部へ表示する。
