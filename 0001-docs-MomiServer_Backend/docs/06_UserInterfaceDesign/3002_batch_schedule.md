# バッチスケジュール画面設計書

## 概要

バッチスケジュールマスタの一覧表示、詳細確認、登録・更新を行う画面。
バッチ定義、対象 Agent、Cron、実行期間、有効状態、優先度を管理する。

## 対象ルート

| 画面 | パス | コンポーネント |
| --- | --- | --- |
| 一覧 | `/master/batch/schedule` | `BatchScheduleList` |
| 詳細 | `/master/batch/schedule/:batchScheduleId` | `BatchScheduleDetail` |
| 互換ルート | `/Master/Batch/Schedule/List` | `BatchScheduleList` |
| 互換ルート | `/Master/Batch/Schedule/Detail/:batchScheduleId` | `BatchScheduleDetail` |

## 関連仕様

### 実装済みの実行状況・完了ログ

2026/10/02のソース確認では、一覧のカレンダー表示に実行状況とログモーダルを実装している。
日・週・月表示で予定日、日表示では時間帯も指定してログを参照する。
成功・失敗・タイムアウトの件数がある場合に実行ログボタンを有効にする。

| 項目 | 表示・操作 |
| --- | --- |
| ログ情報 | 実行ID、予定・開始・終了日時、状態、終了コード、結果メッセージ、標準出力・標準エラー |
| 未取得値 | 日時・終了コードがnullなら「-」表示。0や予定日時で補完しない |
| 出力省略 | output_truncatedがtrueなら保存時に一部省略された旨を表示 |
| ページング | 初期20件。上部に表示範囲・検索結果件数・表示件数選択、下部に前後移動を表示 |
| 取得失敗 | エラー表示と再試行。取得中・0件の状態も区別 |

検索・ページングの契約は[完了ログAPI](../05_API_Design/API/0044_batch_schedule_execution_logs.md)を参照する。
一覧とログモーダルの共通操作は[一覧ページング共通設計](./0001_list_pagination.md)を参照する。
このモーダルは完了ログ専用であり、以下の全履歴・スナップショット表示の完成を示さない。

### 実行予定・実行履歴の表示方針

2026年9月17日決定。以下は追加する画面仕様であり、実装済みであることを示さない。

スケジュール詳細に「今後の実行予定」と「実行履歴」を表示し、各回を選択して詳細を確認できるようにする。
繰り返しスケジュール全体を実行済み・未実行に分類せず、生成された実行要求ごとの状態を表示する。
実行中の要求も確認できるようにし、結果未確認の要求を履歴から除外しない。
実行要求生成済みの行は実行ID、予定日時、対象Agent、実行状態、確認状態で識別する。

| 状態 | 表示内容 |
| --- | --- |
| 未実行 | 実行予定日時、対象Agent、実行予定のパラメータ、配布予定ファイル |
| 実行中 | 開始日時、実行時のパラメータ、配布対象ファイル、現在の状態 |
| 実行済み | 実行結果、開始・終了日時、終了コード、実行時のパラメータ、配布対象ファイル、ログ・成果物 |
| キャンセル・期限切れ | 状態と理由、実行予定だったパラメータ・ファイル。開始済みの場合は実行時の情報 |

キャンセル要求を送っただけでは完了表示にしない。停止確認などの確定した状態を表示する。
`confirmation_status = result_unconfirmed` は「結果未確認」、開始未確認は「開始未確認」と表示し、実行状態とは区別する。
通信断や待ち期限の超過だけで成功・失敗・タイムアウトを推測しない。
開始・終了日時や終了コードを取得できない場合は「未確認」または「未取得」とし、予定日時や0で補完しない。

### パラメータ・ファイル情報の参照時点

| 時点 | 表示元 | 画面上の扱い |
| --- | --- | --- |
| 実行要求の生成前 | 現在の定義から算出した予定値 | 「予定値・変更される可能性あり」と明示。実行IDは付与しない |
| 実行要求の生成後 | 実行要求に保存したパラメータと配布対象ファイルのスナップショット | 当該回に送信する値として表示 |
| 実行後 | 当該実行に使用した実行要求のスナップショットと結果 | 現在の定義を参照して過去の表示を変更しない |

スナップショットは実行要求の生成時に確定する。定義・スケジュール・親ファイルの後日の変更で、生成済み要求の表示内容を暗黙に置き換えない。
エージェントで実行されたことが未確認の場合は「送信対象の値」として表示し、「実際に使用済み」と断定しない。
古い履歴に必要なスナップショットが存在しない場合は「記録なし」と表示し、現在の定義から補完しない。

### ファイル・機密情報の表示

- ファイル一覧には配布ファイル名、サイズ、配布状態を表示する。生成前は配布予定として扱い、配布完了と表示しない。
- 実行要求が参照したファイルを表示し、親ファイルが差し替えられても過去のファイル情報は変更しない。
- UUIDによる実体の保存名や内部の `storage_path` は表示しない。
- ログ・成果物は存在するものを表示する。保存期限などにより取得できない場合はその旨を示す。
- 機密パラメータはマスクする。画面上だけの置換ではなく、表示用APIで平文を返さない。コマンド等に埋め込まれる値も対象とする。
- ファイル取得は対象実行・ファイルへの権限確認を行うAPIを利用する。

### 実装時に具体化する事項

- スケジュール別の実行予定・履歴取得API、ページング、表示対象期間、並び順、更新間隔。
- パラメータとファイル情報のスナップショット保存項目・応答形式、機密項目の識別方法。
- 生成前の予定値の算出範囲、ログ・成果物の参照APIと保持期限の表示。

表示用データの取得方針は [スケジュール詳細設計](../02_SystemDesign/バッチ管理/Details/0002_batch_schedule_detail_design.md) を参照する。

### 既存のスケジュール制御

- スケジューラは有効なスケジュールのみを走査する。
- Cron 式が 5 フィールドの場合は、秒フィールド `0` を補完して Spring の `CronExpression` に渡す。
- `start_date`、`end_date` の範囲外は実行対象外とする。
- 同一 `schedule_id` と `scheduled_fire_time` の重複実行要求は DB 制約で抑止する。
